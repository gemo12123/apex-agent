# 验证与交付参考

在选择测试范围、排查构建失败或准备最终交付时加载本文。

## 基本原则

- 从最靠近改动的快速测试开始，再按影响面扩大。
- 测试失败先判断是本次回归、已有工作区状态，还是外部环境缺失；不要为了通过而删除断言。
- 不编辑或提交 `target/`、`.vite/`、`dist/`、`node_modules/` 等生成物。
- 没有运行的检查明确写“未运行”，不要写成“通过”。

## 按风险选择验证

| 改动类型 | 最低验证 |
| --- | --- |
| 仅 Markdown 文档 | 检查相对链接、文件名、命令和代码事实；确认 UTF-8/LF |
| 单个后端规则类 | 对应 JUnit 测试 |
| 后端执行、Hook、Memory、配置装配 | 相关测试 + 后端完整测试 |
| 单个前端纯函数或组件 | 对应 Vitest 文件 + typecheck |
| Store、reducer、共享类型、布局 | 相关测试 + 前端完整测试 + build |
| REST/SSE/人在回路跨端契约 | 两侧相关测试；优先两侧完整测试与前端 build |
| 启动、代理或外部集成 | 自动测试后再做带真实环境的手工联调 |

## 后端命令

从仓库根目录运行单个测试类：

```bash
mvn -f apex-agent/pom.xml -Dtest=StageToolResolverTest test
```

运行多个类：

```bash
mvn -f apex-agent/pom.xml -Dtest=ChatControllerTest,HumanInLoopResumerTest test
```

运行完整后端测试：

```bash
mvn -f apex-agent/pom.xml test
```

构建可执行包：

```bash
mvn -f apex-agent/pom.xml package
```

涉及真实模型、MCP、Skill 或 JDBC 的路径可能需要 `DASHSCOPE_API_KEY`、外部进程或 PostgreSQL/pgvector。单元测试应尽量使用 mock/fake，不把个人环境作为必需条件。

## 前端命令

运行单个测试文件：

```bash
npm --prefix apex-frontend run test:run -- src/stores/session/reducer.test.ts
```

运行完整测试、类型检查和生产构建：

```bash
npm --prefix apex-frontend run test:run
npm --prefix apex-frontend run typecheck
npm --prefix apex-frontend run build
```

`build` 已包含 `vue-tsc -b`，但在定位类型错误时单独运行 `typecheck` 更快。项目当前没有 lint 脚本。

## 跨端手工烟测

只有任务涉及运行时联调且具备环境时才执行：

1. 设置 `DASHSCOPE_API_KEY`。
2. 检查 `application.yml` 中外部 MCP/Skill 示例路径，不把缺失的本机资源当成代码回归。
3. 启动后端：在 `apex-agent/` 运行 `mvn spring-boot:run`。
4. 启动前端：在 `apex-frontend/` 运行 `npm run dev`。
5. 验证 Agent 列表、普通消息流、终止状态；涉及人在回路时再验证提问或确认恢复。

手工请求必须携带 `X-User-Id`。默认地址和请求示例见 [快速开始](../快速开始.md)。

## 文档校验

文档变更至少确认：

- 所有相对链接指向存在的文件。
- 命令对应 `pom.xml` 或 `package.json` 中真实能力。
- 路径使用当前目录名，未误指向 `front_outdate/`。
- 当前实现和历史计划有明确区分。
- 新文件是 UTF-8、LF，中文可正常读取。

## 最终交付说明

最终回复保持可核验，至少包括：

- 修改了哪些文件和行为。
- 实际运行了哪些测试/构建及结果。
- 因环境或范围未运行哪些验证。
- 已知风险或需要用户后续配置的外部依赖。
