# 跨端契约参考

修改 REST、SSE、人在回路或共享字段时加载本文，并同步检查 [消息标准](../spec/消息标准.md)。

## HTTP 边界

| 语义 | 后端真实路由 | 前端开发代理 |
| --- | --- | --- |
| Agent 列表 | `GET /api/sse/agents` | `/apex-api/sse/agents` |
| 会话流 | `POST /api/sse/chat` | `/apex-api/sse/chat` |
| 只读会话状态 | `GET /api/sse/sessions/{sessionId}?agentKey=...` | `/apex-api/sse/sessions/{sessionId}?agentKey=...` |

所有请求携带 `X-User-Id`。chat 请求用 `sessionId`、`agentKey`、`type` 标识会话；新请求为 `NEW`，恢复为 `HUMAN_RESPONSE`。

只读状态查询按 `X-User-Id + agentKey + sessionId` 校验归属。不存在、跨用户或 agentKey 不匹配统一返回 404；查询不得创建 Turn/Iteration、获取 lease、执行 Hook/模型/工具或发布 END。

## SSE 信封

```json
{
  "event_type": "STREAM_CONTENT",
  "context": {"mode": "react"},
  "messages": []
}
```

- JSON 使用 snake_case；前端视图模型使用 camelCase。
- `context.mode` 固定为线协议字符串 `react`，不是后端执行模式。
- `content_id` 关联正文增量；`tool_call_id` 关联工具与人工恢复；`invocation_id` 关联调用事件；`confirmation_id` 标识一次确认。
- 默认链路不生产 PLAN、TASK_THINK、STREAM_THINK 或 ARTIFACT 事件，但 protocol 与前端仍保留兼容类型。

## 人在回路与刷新回显

后端只发布一个批量 `HUMAN_INTERVENTION` 事件。`messages` 中每项对应一个模型 ToolCall 上的介入请求，按 ToolCall 顺序排列；`interaction_type` 仅用于区分 `ASK_HUMAN` 和 `TOOL_CONFIRMATION`。ASK_HUMAN 的多个问题保留在同一项的 `questions` 中。

恢复请求以 `tool_call_id` 为键，可同时提交问题答案和工具确认：

```json
{
  "call-1": {
    "interaction_type": "ASK_HUMAN",
    "answers": {"0": "答案"}
  },
  "call-2": {
    "interaction_type": "TOOL_CONFIRMATION",
    "confirmation_id": "confirm-id",
    "decision": "APPROVE",
    "updated_args": {"field": "value"}
  }
}
```

- `humanResponse` 允许为空对象。未知 `tool_call_id`、错误类型、错误确认 ID 或非法答案形态会被拒绝。
- 缺失工具键、缺失问题答案、空白字符串和空数组表示“未回复”。core 处理对应项时才采用默认值：确认工具默认批准且不改参数；文本输入、选择、多选和确认问题分别使用协议规定的缺省语义。
- 前端把问题逐题展开为卡片，工具确认各占一张卡片；每张卡片可回答或跳过，只有全部处理后才由最后一张卡片一次提交。跳过项不进入载荷，全部跳过发送 `{}`。
- 后端先保存完整 `SuspendedToolBatch`，再发送一条 `HUMAN_INTERVENTION`。同批所有 PRE Hook 已完成到各自介入点，但真实工具和 POST Hook 尚未执行。
- 前端仅在等待人工态保存 `apex:active-session:v1`，内容为 `{userId, agentKey, sessionId}`。
- 初始化/刷新调用只读状态接口；`HUMAN_IN_THE_LOOP` 的批量 `pendingInteraction` 交给既有 reducer 重建有序卡片，但不自动提交恢复请求。
- 终态、404、切用户或损坏 locator 会清除定位；5xx 保留定位以便重试。
- PostgreSQL 继续使用 `suspended_tool_call` TEXT 列保存批次 JSON。旧版非空单条挂起 JSON 不迁移且会被明确拒绝，升级前必须清理旧 `HUMAN_IN_THE_LOOP` 会话。

## END 与状态

后端实际发送：

```json
{"event_type":"END"}
```

END 表示当前 SSE 传输结束，不一定表示业务会话结束。前端兼容 `context.execution_status`，但当前生产 END 不携带该字段，因此实际按 `pendingInterventions` 推断 `waiting-intervention` 或 `completed`。不得把内部 `AgentRunOutcome` 添加为协议字段。

## 并发与错误映射

- 参数/Header 错误返回 400，且无 END。
- 同一 session lease 冲突同步返回 409，且无 END。
- core 构造/恢复准备失败返回 200 `text/event-stream`，内容严格只有一个 END。
- 每次 NEW/HUMAN_RESPONSE 使用独立 emitter/Publisher；不同 session 不得串写。
- emitter completion/timeout/error 只触发非阻塞取消，不直接发布 END 或释放 lease。
