# 前端开发参考

仅在修改 `apex-frontend/` 时加载本文。交互现状的详细说明见 [前端交互规范](../spec/前端交互规范.md)。

## 技术与结构

- Vue 3 `<script setup>`、TypeScript strict、Pinia、Vue Router。
- Vite 5 构建，Vitest 2 + jsdom 测试。
- `@` 指向 `apex-frontend/src`。
- `src/app/router.ts`：路由（当前只有 `/` 一条，懒加载 `WorkspacePage`）。
- `src/features/workspace/`：当前主工作台页面、组件、时间线与展示转换。其中 `ExecutionRail.vue` 和 `DetailPanel.vue` 是无引用的遗留组件，不代表当前布局。
- `src/stores/session/store.ts`：请求编排、用户操作、流生命周期。
- `src/stores/session/reducer.ts`：把 SSE 信封归并为 `SessionViewModel`。
- `src/types/apex.ts`：传输协议和前端状态类型。
- `src/services/apex-api.ts`：REST/SSE 客户端与 `X-User-Id` 请求头。
- `src/style.css`：全局视觉 token 和布局规则。

## 数据流

```text
组件操作
  → session store
  → apex-api
  → 后端 SSE
  → SseEnvelope
  → reducer
  → SessionViewModel
  → ChatPane / TimelineDrawer / 交互卡片
```

保持职责边界：

- API 层只处理传输、响应解析和流回调。
- Store 管理副作用、AbortController、请求载荷和用户操作。
- Reducer 负责事件到状态的确定性归并；不要在其中发请求或操作 DOM。
- 组件通过 props/emits 交互；页面组件负责组合，不复制 store 状态机。
- `presentation.ts`、`timeline.ts` 负责展示派生，不应成为第二份协议状态。

## 常见变更路径

### 新增或修改 SSE 事件

必须按顺序检查：

1. `types/apex.ts` 中的 detail、envelope 和联合类型。
2. `reducer.ts` 中的状态归并及默认/缺失字段处理。
3. `reducer.test.ts` 中的增量、重复、乱序或终止边界。
4. `store.ts` 是否需要新的恢复动作或请求载荷。
5. 展示组件及组件测试。
6. 后端消息模型和 [消息标准](../spec/消息标准.md)。

不要只让 TypeScript “能编译”；同一个事件可能影响正文、阶段、调用、产物、等待卡片和终止状态。

### 修改人在回路

`ASK_HUMAN` 与 `TOOL_CONFIRMATION` 是两种不同的恢复载荷。修改卡片时同时验证：

- reducer 创建的待处理记录。
- 表单主键是否仍按 `tool_call_id` 组织。
- Store 发送的 `HUMAN_RESPONSE` 载荷。
- 等待期间输入框禁用与 `END` 到达后的状态保持。
- 批准、拒绝、可编辑参数和多问题回答。
- `apex:active-session:v1` 的 locator 保存/清理，以及初始化时只读状态查询。
- 刷新回显只把 `pendingInteraction` 交给 reducer，不自动提交 `HUMAN_RESPONSE`。

### 修改工作台布局或交互

先读相邻组件和测试，再检查：

- `WorkspacePage.vue` 的侧栏、主列和时间线抽屉布局（侧栏/抽屉开关是页面本地 `ref`，不在 store）。
- `ChatPane.vue` 的欢迎态、消息态、输入框与挂起卡片；“执行轨迹”按钮在其 header 右上角，欢迎态下 header 隐藏。
- `WorkspaceSidebar.vue` 的新会话行为与底部“设置”弹层 `TimelineSettingsPopover.vue`（承载 Agent 选择与用户 ID，会话开始后禁用编辑）。
- `TimelineDrawer.vue`、`timeline.ts` 的轨迹展开与产物导出。
- `style.css` 的全局高度、宽度与设计 token（`src/style.test.ts` 直接断言全局样式，改 token 可能弄红测试）。

保留窄屏行为、键盘可用性、按钮语义和现有测试选择器。视觉调整至少验证桌面和窄屏，不要只看单个静态截图。

## 前端不变量

- 当前 API 前缀是 `/apex-api`，Vite 将其重写到 `http://localhost:18083/api`。
- 所有后端请求都携带 `X-User-Id`。
- `selectedAgentKey` 是实际请求使用的 Agent；切换设置不能悄悄改写已经开始的流。
- 新会话重置会话内容，但保留 Agent 选择和用户 ID。
- 没有 `stage_id` 的 react 调用归入前端虚拟阶段 `react-stage`。
- `END` 不能无条件标记完成：`FAILED` 和 `HUMAN_IN_THE_LOOP` 有独立语义，也要兼容缺少 `execution_status` 的消息。注意后端当前发送的 `END` 就是不带 `execution_status` 的，生产路径实际总走兼容分支。
- PLAN/TASK_THINK/STREAM_THINK/ARTIFACT 只用于兼容历史协议；默认后端不生产，前端不得据此假设存在 PlanExecutor。
- 只在等待人工态保留当前 `{userId, agentKey, sessionId}`；终态/404/切用户/损坏数据清除，5xx 保留以便重试。
- Markdown 渲染关闭原始 HTML；不要为了功能方便重新开启不可信 HTML。

## 风格和验证

- 遵循现有无分号 TypeScript 风格、`@/` 导入和显式类型导入。
- 保持 TypeScript strict；不要用无边界的 `any` 绕过协议类型。
- 测试文件与模块相邻，使用 Vitest 和 Vue Test Utils。
- 先运行相关测试，再运行类型检查和构建：

```bash
npm --prefix apex-frontend run test:run -- src/path/to/file.test.ts
npm --prefix apex-frontend run typecheck
npm --prefix apex-frontend run build
```

涉及 reducer、store 或跨组件状态时，再运行完整前端测试：

```bash
npm --prefix apex-frontend run test:run
```

当前没有 `lint` 脚本，不要用 `npm run lint` 作为完成条件。
