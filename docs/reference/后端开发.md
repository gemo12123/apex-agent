# 后端开发参考

仅在修改 `apex-agent/` 时加载本文。项目总体说明见 [项目概览](../overview/项目概览.md)，完整执行链路见 [架构与执行流程](../overview/架构与执行流程.md)。

## 技术与入口

- 构建：Maven；JDK 源码与目标版本均为 25。
- 框架：Spring Boot 3.4.5、Spring AI/Spring AI Alibaba、MyBatis Plus、Lombok。
- 应用入口：`apex-agent/src/main/java/org/gemo/apex/ApexApplication.java`。
- SSE Web 入口：`web/controller/ChatController.java` → `web/service/ChatService.java` → `core/SuperAgentCoordinator.java`。`SuperAgentCoordinator` 负责同一 `sessionId` 的并发防护（重复请求返回 409）、`chatStreamExecutor` 线程池异步派发，以及在 `finally` 中补发 `END` 并清理注册表。
- 会话装配：`core/SuperAgentFactory.java`（当前入口是 `create(ChatRequest, SseEmitter)`，按 `NEW`/`HUMAN_RESPONSE` 分流到 `createForNew`/`createForResume`；`executeContext` 是无调用点的残留 API）与 `core/SuperAgentSessionService.java`（`createContext`/`resumeContext` 的真正实现）。
- 执行循环：`core/SuperAgent.java` 与 `core/engine/`。
- 配置入口：`src/main/resources/application.yml`，绑定类位于 `config/`。注意 `spring.profiles.active: dev`：`application-dev.yml` 会覆盖数据源为 MySQL，并设置 `apex.memory.enabled: false`（记忆与 Skill 学习 Hook 默认不生效）。

## 按变更类型定位

### Agent 定义或 workspace

先检查：

- `definition/agent/AgentDefinitionClasspathYmlLoader.java`
- `definition/agent/AgentDefinition.java`
- `definition/agent/AgentWorkspaceConfig.java`
- `config/model/AgentConfig.java`
- `src/main/resources/agents/<agentKey>/`

全局配置与 workspace 配置会合并；workspace 的非空 allow 列表会优先于全局列表，显式 workspace hooks 会覆盖全局 hooks。Prompt 缺失时存在默认回退。修改加载优先级时必须补 loader 测试。

### 执行模式或工具可见性

先检查：

- `core/engine/StageToolResolver.java`
- `component/interceptor/ToolInterceptor.java`
- `tool/WritePlanTool.java`
- `tool/UpdatePlanTool.java`

`react` 与 `plan-executor` 不能共用同一套假设。`react` 下 `write_plan_tool` 和 `update_plan_tool` 都不可调用；`plan-executor` 无计划时只允许写计划，已有计划后 `update_plan_tool` 可调用且 `write_plan_tool` 被移除。`ToolInterceptor` 是运行时二次守卫，额外规则是“有计划但无 `RUNNING` 阶段时只允许 `update_plan_tool`”。更改规则时同时覆盖“无计划、运行中、重规划、非法状态”。

### 工具、MCP、SubAgent 或 Skill

先检查：

- 内置注册：`component/tool/BuiltInToolProvider.java`
- 聚合注册：`component/tool/GlobalToolRegistry.java`
- 工具执行：`core/engine/ToolCallProcessor.java`
- MCP 定义：`definition/mcp/`
- SubAgent：`tool/SubAgentToolCallback.java`
- Skill：`skills/` 与 `definition/skill/`

工具名称是跨配置、Prompt、Hook 匹配和前端展示的稳定键。重命名工具必须搜索所有字符串引用和测试数据。

### 生命周期 Hook 或工具确认

当前生命周期点定义在 `hook/lifecycle/HookPoint.java`：

- `TURN_START`
- `TRACE_START`
- `PRE_MODEL_CALL`
- `POST_MODEL_CALL`
- `PRE_TOOL_CALL`
- `POST_TOOL_CALL`
- `TRACE_END`
- `TURN_END`

分发器是 `hook/lifecycle/DefaultAgentLifecycleHookRuntime`（旧的 `hook/DefaultAgentHookRuntime` 仍在但已不承担主链路分发）。工具前后 Hook 接口位于 `hook/tool/`；`hook/tool/builtin/` 只有 `ToolConfirmHook` 与 `PlainTextTruncateHook`，Skill 相关的 `SkillUsageRecorderHook`、`SkillExperienceAugmentHook` 位于 `skills/learning/`。变更时必须验证：

- Hook 的排序、启用状态和工具匹配。
- 参数或结果改写是否写回运行时上下文。
- 非法流程动作是否被拒绝。
- Hook 异常后的主流程策略。
- `REQUEST_CONFIRMATION` 的挂起、持久化和恢复是否完整。

### Memory 或会话搜索

先按职责定位：

- 存储切换：`memory/config/MemoryConfiguration.java`
- 会话上下文：`memory/session/`
- 摘要压缩：`memory/conversation/`
- 召回：`memory/recall/`
- 抽取与写入：`memory/extract/`、`memory/write/`
- 持久化：`memory/persistence/`
- 搜索：`memory/search/`
- 管理接口：`memory/web/`

默认 `apex.memory.store.type` 是 `in-memory`，且激活的 `dev` profile 里 `apex.memory.enabled: false`，记忆链路默认整体关闭。记忆类型枚举 `memory/model/MemoryType` 是 `LONG_TERM`、`FACT`、`EXECUTION_HISTORY`、`AGENT_EXPERIENCE`。JDBC schema（`db/memory-schema-postgresql.sql`）和 `memory/search/` 向量搜索是 PostgreSQL/pgvector 专用实现，但 `pom.xml` 当前保留 MySQL 驱动、注释掉了 PostgreSQL 驱动，`dev` profile 数据源也是 MySQL；不要在未核对依赖、URL、schema 和扩展的情况下宣称 JDBC 可直接使用。

## 后端不变量

- `UserContextFilter` 从 `X-User-Id` 建立用户上下文，异步执行通过 `TaskDecorator` 传播并在结束时清理。
- 新会话与恢复会话走不同装配路径；恢复前要校验持久化上下文和人在回路状态。
- `SuperAgent` 有最大迭代次数，并负责 turn/trace 生命周期、模型调用、工具调用、挂起和结束收尾。
- 工具确认必须保留 `toolCallId`、`invocationId`、确认 ID、可编辑参数和已执行 Hook 信息（`PendingToolExecution.executedPreHookBeans`），避免恢复时重复执行。
- SSE 消息通过 `message/` 模型和 `util/MessageUtils.java` 发出；主链路实际发送的事件清单以 [消息标准](../spec/消息标准.md) 为准，协议改动遵循 [跨端契约](跨端契约.md)。
- `SuperAgentFactory` 与 `SuperAgent` 各有一个注入 no-op 依赖的降级构造器，生产装配依赖 `@Autowired` 长构造器；改构造器签名时警惕误用短构造器导致 Hook 静默失效。
- 工具执行编排在 `ToolCallProcessor`（Hook 分发、确认挂起、`ask_human` 分流、结果落库）；`CustomToolCallingManager` 仍是 Spring 的 `ToolCallingManager` bean，但只负责底层真实工具调用，其中与挂起/Hook 相关的方法是死代码。
- 外部 MCP server 和本地 Skill 路径不是仓库自带资源。测试应使用替身或临时资源，不能依赖作者机器路径。

## 实现与测试习惯

- 遵循相邻代码的包结构、命名和依赖注入方式，不在功能改动中顺手做全局风格重构。
- 业务逻辑优先放入 service/engine/runtime 类，Controller 只做 HTTP 边界处理。
- 测试使用 JUnit 5；测试类放在与生产包对应的 `src/test/java` 路径。
- 纯规则类优先写快速单元测试；涉及 Spring 装配时才扩大上下文。
- 针对单类先运行：

```bash
mvn -f apex-agent/pom.xml -Dtest=ClassName test
```

- 后端变更完成后至少运行受影响测试；跨核心执行链路的改动应运行完整：

```bash
mvn -f apex-agent/pom.xml test
```
