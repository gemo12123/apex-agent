# 项目概览

## 项目定位

Apex Agent 是“可独立运行的 Agent runtime + Spring Boot platform + Vue 工作台”的组合仓库。当前后端只有一个 ReAct 执行循环，支持生命周期 Hook、模型流、多工具调用、消息压缩、请求级取消、人工挂起/恢复以及 PostgreSQL 持久化。

## 后端模块

父工程固定为八个模块：

- `protocol`：REST/SSE DTO、13 类事件模型与 Golden File。
- `common`：中立 Agent/Session/Turn/Iteration、工具、快照、取消和 JSON 模型。
- `core-extension`：模型、工具、事件、存储、生命周期等纯接口端口。
- `core`：唯一 ReAct、11 个生命周期、压缩、多工具、挂起和五分支恢复。
- `kit`：ask_human、工具确认、文本截断和 Hook 组合辅助。
- `runtime`：Builder、Provider/Registry、Spring AI、内存仓储、lease、Once Publisher、Skill、MCP、SubAgent 与资源关闭。
- `platform`：Spring Boot、HTTP/SSE、用户上下文、PostgreSQL/Flyway 和 Repository Adapter。
- `memory`：无依赖 `packaging=pom` 占位模块，源码仅在 `archive/main` 历史归档，不编译、不测试、不进入默认依赖图。

模块依赖由自动架构测试和 Maven Enforcer 守护；`legacy`、PlanExecutor、Stage、SuperAgent、重复 Hook Runtime 与 Fastjson 已删除。

## 主执行链

```text
POST /api/sse/chat
  -> ChatController / ChatService
  -> ApexAgentRuntime.newAgent | resumeAgent
  -> session execution lease + request-scoped publisher/token
  -> ApexAgentExecution.run
  -> ApexAgent 唯一 ReAct 循环
  -> model / compression / ordered tools / HITL
  -> Once END
  -> finally 释放 lease 与活动登记
```

状态查询 `GET /api/sse/sessions/{sessionId}?agentKey=...` 只读取持久化快照，用于刷新后恢复两类 HITL 卡片，不进入执行链。

## 默认能力

默认可用：

- Programmatic 默认 Agent 与 ReAct Prompt。
- `activate_skill`、普通文件 Skill 及受 enabledSkills 约束的资源读取。
- 进程内 Session/Conversation Repository，可用于 runtime-only 场景。
- platform PostgreSQL 三表持久化和 `1.0.0` TEXT 快照。
- 可选 MCP 与 HTTP SubAgent Adapter。

默认不包含：

- PlanExecutor、计划工具和运行 Stage。
- 长期 Memory 召回、`session_search`、Memory 管理和 Skill Learning。
- 远程 SubAgent 的嵌套人工介入。
- 跨 Repository 原子事务、未知快照升级、分布式 lease 或多副本安全。

## 前端工作台

`apex-frontend` 使用 Vue 3、Pinia、Vite 和 Vitest。它负责：

- Agent 列表、NEW/HUMAN_RESPONSE 请求和 SSE 消费。
- STREAM_CONTENT、兼容计划/调用/产物事件的状态投影。
- ASK_HUMAN 与 TOOL_CONFIRMATION 卡片和恢复载荷。
- `apex:active-session:v1` 定位持久化与刷新回显。
- END 缺少 `execution_status` 时的兼容状态推断。

默认后端不生产 PLAN/TASK_THINK/STREAM_THINK/ARTIFACT；前端保留相关兼容渲染，不能据此推断后端仍有计划执行能力。

## 数据库与部署边界

platform 唯一数据库是 PostgreSQL。Flyway 创建 session、dialogue message、dialogue summary 三表；快照和长载荷用 TEXT，不兼容旧 MySQL schema。

本期只支持 `replicas=1`。滚动升级必须停旧再启新，禁止让两个副本重叠；共享数据库不能避免同 session 的跨进程并发。
