# 快速开始

## 环境

- JDK 25
- Maven 3.9+（仓库当前也可由既有 Maven 3.8.1 环境执行）
- Node.js 20+
- platform：PostgreSQL 16+ 与模型供应商密钥，例如 `DASHSCOPE_API_KEY`
- PostgreSQL 集成测试：Docker/Testcontainers

## 先运行验证

```bash
mvn -f apex-agent/pom.xml test
npm --prefix apex-frontend run test:run
npm --prefix apex-frontend run typecheck
npm --prefix apex-frontend run build
```

## runtime-only

`runtime` 不依赖 Spring IoC，可用 Programmatic 默认 Agent 与内存 Repository：

```java
try (var runtime = ApexAgentRuntime.builder()
        .modelGateway(modelGateway)
        .build()) {
    var execution = runtime.newAgent(
            new AgentRequest("session-1", "default", "user-1", "你好"));
    execution.run();
}
```

Builder 必须且只能设置一个 `modelGateway(...)` 或 `chatModel(...)`。默认 Publisher 把 JSON 事件写到标准输出；产品接入应传入请求级 `AgentEventPublisherFactory`。

## platform + PostgreSQL

1. 创建空数据库 `apex_agent`。
2. 设置环境变量：

```powershell
$env:APEX_DB_URL='jdbc:postgresql://localhost:5432/apex_agent'
$env:APEX_DB_USER='apex_agent'
$env:APEX_DB_PASSWORD='your-password'
$env:DASHSCOPE_API_KEY='your-key'
```

3. 启动后端：

```bash
mvn -f apex-agent/pom.xml -pl platform -am spring-boot:run
```

Flyway 自动创建三张 `apex_agent_*` 表。默认 Agent 配置位于 `platform/src/main/resources/application.yml`；Prompt 位于 `platform/src/main/resources/agents/default_agent/REACT_PROMPT.md`。

4. 启动前端：

```bash
npm --prefix apex-frontend run dev
```

前端默认通过 `/apex-api` 代理到 `http://localhost:18083/api`。

## HTTP 示例

Agent 列表：

```bash
curl -H "X-User-Id: demo-user" http://localhost:18083/api/sse/agents
```

新会话：

```bash
curl -N -X POST http://localhost:18083/api/sse/chat \
  -H "Content-Type: application/json" \
  -H "X-User-Id: demo-user" \
  -d '{"sessionId":"session-1","agentKey":"default_agent","type":"NEW","query":"你好"}'
```

只读状态：

```bash
curl -H "X-User-Id: demo-user" \
  "http://localhost:18083/api/sse/sessions/session-1?agentKey=default_agent"
```

恢复请求使用同一 `sessionId`、`agentKey`，`type` 设为 `HUMAN_RESPONSE` 并携带 `humanResponse`。

## 可选集成

- Skill：platform 在没有自定义 `SkillProvider` Bean 时默认从 `classpath:skills` 加载元信息；standalone runtime 默认不加载 Skill，只接收 Builder 注入的单个最终 `SkillProvider`。`SKILL.md` 正文和子资源只在工具调用时读取。资源读取只允许已启用 Skill，Skill 激活工具和状态 Hook 不会自动注册。
- MCP：platform 通过 `spring.ai.mcp.client.*` 配置 Spring AI MCP Client；发现的工具名仍须进入 Agent 的 `tools.available` 和会话 `enabledTools`。
- SubAgent：使用目标 Agent 的 chat/SSE 地址；子 Agent 必须在单次 NEW 内完成，不能要求人工介入。

### 显式配置 Skill 激活

runtime-only 场景自行创建最终 Provider，并使用单 Provider 接口组合 kit 实现：

```java
SkillProvider skillProvider = new FileSkillProvider(Path.of("./skills"));
var runtime = ApexAgentRuntime.builder()
        .modelGateway(modelGateway)
        .agentDefinition(agentDefinition)
        .skillProvider(skillProvider)
        .registerTool(new ActivateSkillTool(skillProvider))
        .registerHook(new SkillActivationStateHook())
        .build();
```

每个 Skill 位于加载根目录的直接子目录中，必须包含带 `name`、`description` front matter 的 `SKILL.md`。Provider 的 `loadSkills()` 返回可继承的 `SkillMeta`；文件 Provider 同时缓存对应 `SkillDefinition` 和全部 `SkillResource` 元信息，但此时 `instructions` 与资源 `content` 均为 `null`。`loadSkill(skillName)` 首次读取并缓存 instructions，`loadResource(...)` 首次读取并缓存资源 content。`SkillResource` 提供相对路径、含扩展名文件名和 MIME 类型。单参数资源路径使用 `skillName/相对资源路径`，例如 `pdf/references/guide.md`。

Agent 定义还必须把 `activate_skill` 加入 `tools.available/default-enabled`，并显式绑定状态 Hook：

```yaml
tools:
  available: [activate_skill]
  default-enabled: [activate_skill]
skills: [pdf]
hooks:
  POST_TOOL_CALL:
    - id: skill-activation-state
      hook: skillActivationStateHook
      order: 0
      enabled: true
      tools: [activate_skill]
```

platform 场景可把同一组合声明为普通 Bean，现有配置会自动收集：

```java
@Bean
SkillProvider workspaceSkills() {
    return new FileSkillProvider(Path.of("./workspace-skills"));
}

@Bean
AgentTool activateSkillTool(SkillProvider workspaceSkills) {
    return new ActivateSkillTool(workspaceSkills);
}

@Bean
SkillActivationStateHook skillActivationStateHook() {
    return new SkillActivationStateHook();
}
```

未声明 `SkillProvider` Bean 时，platform 使用以下路径创建默认文件 Provider；只要声明了任意自定义 Provider Bean，就完全使用这些 Bean，不再创建默认文件 Provider，此路径也不会参与加载。多个 Bean 按 Spring 顺序交给 platform 的 `RuntimeSkillRegistry` 聚合，同名 Skill 由后注册的 Provider 覆盖：

```yaml
apex:
  platform:
    skills:
      path: classpath:skills
```

若不注册状态 Hook，工具仍会返回 instructions，但 `activatedSkills` 不会改变。自定义工具名称不受限制；它可以输出 kit 的 `activatedSkill` metadata 复用标准 Hook，也可以绑定自己的 POST_TOOL_CALL Hook 返回 `SkillActivationDelta`。

长期 Memory、`session_search`、Memory 管理和 Skill Learning 仅在 `memory/archive/main` 保存历史源码，不能通过配置启用。

## 已知限制

- 只支持单实例；升级时不得有两个副本重叠。
- 快照只支持 `1.0.0`。
- 不支持旧 MySQL 数据库直接迁移或混用。
- PostgreSQL/Testcontainers 未实际运行时必须写“未验证”，不能由 Maven BUILD SUCCESS 推断数据库行为通过。
- 自定义工具若不响应 CancellationToken，runtime 不会用超时或 grace period 强制结束。

生产部署和回滚见 [部署、发布与回滚](部署、发布与回滚.md)。
