# 部署、发布与回滚

## 发布前检查

```bash
mvn -f apex-agent/pom.xml clean verify
npm --prefix apex-frontend run test:run
npm --prefix apex-frontend run typecheck
npm --prefix apex-frontend run build
```

具备 Docker 时必须运行 `PostgresRepositoryIntegrationTest`，验证空库 Flyway、长 TEXT、幂等和重启恢复。没有 Docker 时只能记录环境豁免与未验证，不能写成通过。

## 配置迁移

- 应用入口和配置已迁到 platform；旧 global/workspace、PlanExecutor/Stage/执行模式配置不兼容。
- 数据库只支持 PostgreSQL，通过 `APEX_DB_URL`、`APEX_DB_USER`、`APEX_DB_PASSWORD` 配置。
- 必须使用新空库执行 Flyway。不要让新 platform 读取旧 MySQL 数据。
- 快照格式只支持 `1.0.0`，未知版本不会自动升级。
- 长期 Memory、`session_search`、Memory 管理和 Skill Learning 不再是默认产品能力。

## 部署约束

- 固定 `replicas=1`。
- 升级采用“停旧 -> 确认进程退出 -> 启新”，接受短暂停机。
- Kubernetes/RollingUpdate 不得设置会产生副本重叠的 `maxSurge`；在分布式 Coordinator 落地前不要水平扩展。
- 健康检查成功不代表 PostgreSQL 数据兼容或外部 MCP/Skill 可用，应分别验证。

## 发布说明

本次架构发布的默认变化：

- 删除 PlanExecutor、Stage、计划工具和运行模式；后端仅保留 ReAct。
- 后端类型统一为 ApexAgent，删除 legacy、SuperAgent、重复 Hook Runtime 和 Fastjson。
- platform 使用 PostgreSQL 三表和 TEXT 快照，不兼容旧 MySQL。
- runtime 支持请求级主动取消；模型/MCP/HTTP Adapter 传播取消，lease 在 run finally 释放。
- 新增只读会话状态接口和前端两类 HITL 刷新回显。
- memory 只剩非编译历史归档，默认没有长期召回、session_search 或 Skill Learning。
- 单实例限制不变，远程 SubAgent HITL 与快照跨版本升级不支持。

## 回滚

1. 停止新 platform，确认没有活动 execution。
2. 保留新 PostgreSQL 数据库和日志用于调查，不让旧版本读取它。
3. 恢复上一 legacy 发布物及其匹配配置。
4. 恢复/连接上一版本专用旧数据库备份；不要尝试让旧版本读取新 PostgreSQL TEXT 快照，也不要让新版本读取旧 MySQL。
5. 恢复旧前端时同时恢复与其匹配的后端协议版本。

回滚是版本与数据库成套切换，不提供在线双写、schema 降级或跨版本快照转换。
