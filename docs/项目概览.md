# 项目概览

## 项目定位

`apex-agent` 当前是一个“Agent 运行时 + 工作台前端”的组合仓库，而不是单纯的模型调用示例。

它解决的是一整条会话执行链路：

- 接收用户请求并校验用户上下文
- 基于 agent 定义装配工具、提示词和 Hook
- 在 `react` 或 `plan-executor` 模式下执行
- 在执行过程中支持 `ask_human` 与工具确认
- 记录会话、摘要、执行历史、经验记忆
- 通过 SSE 向前端持续推送结构化事件
- 由前端将事件重建成聊天、计划、调用轨迹和产物视图

## 仓库主模块

### `apex-agent/`

Spring Boot 后端。负责：

- Agent 执行引擎
- 工具注册与调用
- MCP / SubAgent / Skills 集成
- 会话与记忆存储
- SSE 接口
- 记忆管理接口

### `apex-frontend/`

Vue 3 工作台。负责：

- 加载 agent 列表
- 发起和恢复会话
- 渲染 `STREAM_CONTENT`
- 可视化计划阶段、工具调用、产物
- 响应 `ASK_HUMAN`
- 响应 `TOOL_CONFIRMATION`

### `docs/`

围绕当前实现维护的说明文档，重点覆盖：

- 项目定位
- 启动方式
- 架构与执行流
- SSE 消息协议

## 后端能力地图

### 1. Agent 定义与 workspace 解析

后端通过 `AgentDefinitionClasspathYmlLoader` 解析 agent 定义，组合来源包括：

- `application.yml` 里的全局 agent 配置
- `agents/<agentKey>/config.yml` 里的 workspace 白名单与 Hook
- workspace 下的 prompt 文件
- 缺失时回退到默认 prompt 模板

这意味着 agent 的“运行定义”不是单一文件，而是全局配置和 workspace 配置的合并结果。

### 2. 执行引擎

当前主执行链路只有一个内部阶段：`EXECUTION`。

在这个阶段下，系统支持两种模式：

- `react`
  直接进入“思考 - 调工具 - 继续执行”的循环
- `plan-executor`
  先要求模型创建计划，再通过 `update_plan_tool` 推进阶段状态与任务思考

### 3. 工具体系

当前工具来自四类来源：

- 内置工具：`ask_human`、`write_plan_tool`、`update_plan_tool`、`session_search`
- MCP 工具：通过 stdio 拉起外部 MCP server
- SubAgent 工具：通过 HTTP + SSE 调用其他 agent
- Skills 工具：以 `activate_skill` 为入口，动态读取文件系统 skill

### 4. Hook 体系

工具调用并不是模型直接执行，而是会经过统一 Hook 运行时：

- `pre-tool-call`
  可拦截、改写参数，或要求前端先确认
- `post-tool-call`
  可加工工具结果，例如纯文本截断、skill 经验增强、skill 使用记录

### 5. Memory 系统

当前实现的记忆不只是一份聊天记录，至少包括：

- 会话元数据
- 对话消息
- 对话摘要
- 用户画像记忆
- 执行历史记忆
- Agent 经验记忆
- 会话搜索索引

默认存储是 `in-memory`，切到 `jdbc` 后会启用 JDBC 版仓储实现。

### 6. Skill 经验学习

仓库已经实现 `activate_skill` 相关的经验学习链路：

- 记录 skill 使用消息
- 按阈值聚合会话片段
- 定时抽取 skill 经验
- 将经验记忆再次注入 skill 激活上下文

这部分不是设计稿，源码和测试都已经存在。

## 前端能力地图

前端当前不是一个简单聊天框，而是面向 SSE 协议的状态工作台：

- `ChatPane` 负责欢迎态、消息流、挂起输入/确认卡片与统一输入区
- `TimelineDrawer` + `timeline.ts` 负责阶段、调用和产物的执行轨迹抽屉与产物导出
- `WorkspaceSidebar` 负责新建会话、历史占位与底部设置弹层（`TimelineSettingsPopover`，承载 Agent 选择与用户 ID）
- `session store` + `reducer` 负责把 SSE envelope 还原成前端视图模型

（`ExecutionRail.vue` 与 `DetailPanel.vue` 是旧布局的无引用遗留组件，不代表当前界面。）

当前前端仍保留对 `STREAM_THINK` 的兼容，重点消费的是：

- `STREAM_CONTENT`
- `PLAN_DECLARED`
- `PLAN_CHANGE`
- `INVOCATION_DECLARED` / `INVOCATION_CHANGE`（后端仅在子 Agent 场景透传）
- `ARTIFACT_DECLARED` / `ARTIFACT_CHANGE`（协议保留，后端当前无生产者）
- `ASK_HUMAN`
- `TOOL_CONFIRMATION`
- `END`

已知缺口：后端在 plan-executor 模式下的主文本通道 `TASK_THINK_CHANGE` 前端尚未消费，详见 [消息标准](消息标准.md)。

## 当前仓库状态与注意点

### 1. 仓库内置资源并不等于配置里声明的全部能力

当前资源目录里真正存在的 agent workspace 很少：

- `agents/codex/REACT_PROMPT.md`
- `agents/deer-flow/REACT_PROMPT.md`
- `agents/deer-flow/config.yml`

但 `application.yml` 中同时声明了四个 agent 与外部资源：

- `default_agent`
- `deer-flow`
- `meeting_tool`
- `contacts_tool`
- 外部 MCP 路径
- 外部 skill 目录

其中 `default_agent`、`meeting_tool`、`contacts_tool` 的 workspace 目录在 classpath 中并不存在，而现存的 `agents/codex/` 没有任何 agent 引用。所以阅读或部署这个项目时，必须区分：

- 仓库自带实现
- 本地示例配置
- 真实落地所需的外部资源

### 1.1 激活的是 dev profile

`application.yml` 设置 `spring.profiles.active: dev`，而 `application-dev.yml` 会覆盖数据源为 MySQL，并把 `apex.memory.enabled` 设为 `false`。也就是说默认启动形态下，记忆链路与 Skill 经验学习 Hook 都是关闭/未绑定状态；验证这些能力前要先调整 profile 或配置。

### 2. JDBC 路径需要自行对齐依赖

代码中的 memory schema、session search 和 `pgvector` 逻辑明显围绕 PostgreSQL 展开，但当前 `pom.xml` 默认保留的是 MySQL 驱动，并把 PostgreSQL 驱动注释掉了。
如果你要真正启用 JDBC 记忆，请先对齐：

- JDBC 驱动依赖
- `spring.datasource.*`
- schema 初始化
- `pgvector` 扩展
