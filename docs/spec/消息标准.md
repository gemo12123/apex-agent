# Apex Agent 消息标准

## 信封

所有 SSE 数据使用：

```json
{
  "event_type": "STREAM_CONTENT",
  "context": {"mode": "react"},
  "messages": []
}
```

- `event_type`：事件类型。
- `context.mode`：默认固定为线协议字符串 `react`，不是可切换执行模式。
- JSON 字段使用 snake_case。
- 字段为空时是否省略由 protocol DTO/Jackson 规则决定；以 Golden File 为准。

## 默认生产事件

### TURN_START / ITERATION_START / ITERATION_END / TURN_END

对话页的实时执行边界事件。它们均使用空 `messages`，并在 `context` 中携带 `turn_no`；Iteration 事件额外携带 `iteration_no`，`ITERATION_START` 以 `resumed` 标记人工介入恢复后的下一次模型调用。开始事件的 `execution_status` 为 `IN_PROGRESS`，结束事件携带对应 Turn 或 Iteration 的终态。边界事件只用于实时分组，不作为历史回放数据源。

### STREAM_CONTENT

模型正文增量。`context.content_id` 标识同一段内容，`messages[*].content` 依次追加。

```json
{"event_type":"STREAM_CONTENT","context":{"content_id":"content-1","mode":"react"},"messages":[{"content":"hello"}]}
```

### HUMAN_INTERVENTION

执行已持久化为 `HUMAN_IN_THE_LOOP`。这是唯一人工介入事件，`messages` 按模型 ToolCall 顺序排列，每项用 `interaction_type` 区分：

- `ASK_HUMAN`：包含 `tool_call_id`、`invocation_id`、`tool_name` 和同一工具调用下的 `questions`；问题支持 TEXT_INPUT、SINGLE_SELECT、MULTI_SELECT、CONFIRM。
- `TOOL_CONFIRMATION`：包含 `confirmation_id`、`tool_call_id`、`invocation_id`、风险、摘要和可编辑字段。

同批存在任意介入时，真实工具和 POST_TOOL_CALL 均未执行。旧的顶层 ASK_HUMAN、TOOL_CONFIRMATION 事件已删除。

```json
{
  "event_type": "HUMAN_INTERVENTION",
  "context": {"mode": "react"},
  "messages": [
    {
      "interaction_type": "ASK_HUMAN",
      "tool_call_id": "call-1",
      "invocation_id": "invocation-1",
      "tool_name": "ask_human",
      "questions": [
        {"input_type": "TEXT_INPUT", "question": "请输入内容", "options": []}
      ]
    },
    {
      "interaction_type": "TOOL_CONFIRMATION",
      "tool_call_id": "call-2",
      "confirmation_id": "confirmation-2",
      "invocation_id": "invocation-2",
      "tool_name": "meeting_tool",
      "tool_display_name": "会议工具",
      "title": "确认执行",
      "risk_level": "MEDIUM",
      "editable": false,
      "confirm_label": "批准",
      "deny_label": "拒绝",
      "display_fields": [],
      "editable_fields": []
    }
  ]
}
```

### INVOCATION_DECLARED / INVOCATION_CHANGE

用于工具/远程调用轨迹。Core 只为真正进入 `AgentTool.execute` 的调用自动发送基础生命周期：

1. PRE Hook 与人工恢复决议结束后、工具执行前发送 `INVOCATION_DECLARED`。`content` 是最终解析参数的原始 JSON；`invocation_type=tool`、`click_effect=none`、`complete=false`、`render_type=json`。
2. 工具返回、POST Hook 修改结果并成功持久化最终 `ToolResult` 后，发送一个 `INVOCATION_CHANGE` 信封。`messages` 依次为 `CONTENT_APPEND`（最终结果、`render_type=text`）和 `STATUS_CHANGE`（`COMPLETE` 或 `FAILED`）。
3. 工具调用取消时，先持久化取消结果，再尽力发送状态为 `CANCELLED` 的同结构变化事件。

禁用、不可用、PRE 阻断、直接结果、人工挂起和用户拒绝都没有 Invocation。挂起恢复后若真实执行工具，沿用快照中稳定的 `invocation_id`。声明发布失败时不执行工具；最终结果持久化失败时不发送虚假终态。工具抛出的运行时异常为 `FAILED`，普通返回不根据结果文本猜测失败。

```json
{"event_type":"INVOCATION_DECLARED","context":{"mode":"react","invocation_id":"invocation-1","executor":"weather"},"messages":[{"invocation_id":"invocation-1","name":"weather","invocation_type":"tool","click_effect":"none","content":"{\"city\":\"北京\"}","complete":false,"render_type":"json"}]}
```

```json
{"event_type":"INVOCATION_CHANGE","context":{"mode":"react","invocation_id":"invocation-1","executor":"weather"},"messages":[{"change_type":"CONTENT_APPEND","invocation_id":"invocation-1","content":"晴","render_type":"text"},{"change_type":"STATUS_CHANGE","invocation_id":"invocation-1","status":"COMPLETE"}]}
```

`messages[*].invocation_id` 是实际更新的调用节点。子调用声明可携带 `parent_invocation_id`；HTTP SubAgent 转发时，外层 `context.invocation_id` 改为当前父工具 ID，用于 observer 所有权校验，而消息内 ID 保持子节点 ID。直属子声明缺少父 ID 时补为当前父 ID；更深层已经携带的父 ID 保持不变。

`ToolExecutionObserver` 仍可上报工具内部进度或嵌套调用，但不得发布 END、人工交互或其他非白名单事件。

### TASK_ERROR

Agent 循环内发生 RuntimeException 时发布。`messages` 恰好一项，只包含异常 message；空 message 使用“Agent 执行失败”，不包含错误码、cause 或堆栈。

```json
{"event_type":"TASK_ERROR","context":{"mode":"react"},"messages":[{"message":"model down"}]}
```

### END

结束当前 SSE 传输。实际载荷精确为：

```json
{"event_type":"END"}
```

END 不包含 `execution_status`、code 或 payload，并由请求级 Once Publisher 保证至多一次。内部 `AgentRunOutcome` 不进入协议。

## 兼容事件

protocol 仍可序列化/反序列化以下事件，前端也保留相应兼容类型或展示；默认 ReAct 链不生产它们：

- STREAM_THINK
- ARTIFACT_DECLARED / ARTIFACT_CHANGE

PLAN_DECLARED、PLAN_CHANGE、TASK_THINK_DECLARED、TASK_THINK_CHANGE 已从协议类型中删除，收到这些 `event_type` 时按未知事件处理。其余兼容事件的精确 JSON 见 `protocol/src/test/resources/golden/protocol/*.compat.json`。

## 只读会话状态

`GET /api/sse/sessions/{sessionId}?agentKey=...` 返回 camelCase DTO：

```json
{
  "sessionId": "session-1",
  "agentKey": "default_agent",
  "executionStatus": "HUMAN_IN_THE_LOOP",
  "pendingInteraction": {
    "event_type": "HUMAN_INTERVENTION",
    "context": {},
    "messages": []
  }
}
```

`pendingInteraction` 只允许一个批量 HUMAN_INTERVENTION 或 null，直接由持久化批次映射，不重新执行 core。COMPLETED/FAILED 等非人工态必须为 null。

## 对话历史

- `GET /api/sse/sessions` 按 `X-User-Id` 返回当前用户的会话列表，包含 `sessionId`、`agentKey`、`sessionSummary`、`executionStatus` 与 `lastActiveTime`。
- `GET /api/sse/sessions/{sessionId}/history` 仅按 `X-User-Id` 校验所有权，不接收 `agentKey`。它从 `apex_agent_dialogue_message` 的全部原始行重建 Turn、Iteration、正文和工具结果；包括已被压缩标记的行。
- `session_summary` 只在首次 NEW 提问后写入首个问题前 15 个 Unicode 字符；`iteration_no` 在用户消息中为 null，在助手与工具结果消息中标识所属迭代。

## 恢复协议

- chat 请求 `type=HUMAN_RESPONSE`，复用原 `sessionId` 与 `agentKey`。
- `humanResponse` 是以 `tool_call_id` 为键的稀疏映射，允许 `{}`。ASK_HUMAN 值含 `answers`；TOOL_CONFIRMATION 值含 `confirmation_id`、`decision`，批准时可含 `updated_args`。
- 未出现的工具键及未出现的问题索引表示未回复；空白字符串和空数组也按未回复处理。默认值由 core 处理对应介入项时即时解析，不由前端补齐。
- 显式提交的未知工具 ID、错误 `interaction_type`、错误确认 ID 或非法答案形态会被拒绝。
- 刷新查询只回显，不自动提交 HUMAN_RESPONSE。

## 错误与并发

- 请求/Header 无效：HTTP 400，无 END。
- session busy：HTTP 409，无 END。
- core 准备失败：HTTP 200 `text/event-stream`，仅一个 END。
- 已进入 Agent 循环的 RuntimeException 依次发送 TASK_ERROR、END；正常、取消或挂起的已开始传输仅由 execution 收口 END。
- SSE 连接自身断开或发送失败时，无法保证在同一连接上继续送达 TASK_ERROR 或 END。

## 变更要求

修改事件时必须同步 protocol DTO/Golden File、生产发送点、前端联合类型/reducer/store、跨端测试和本文。不得只添加 DTO 而没有生产/消费语义，也不得把兼容 DTO 描述为默认能力。
