# Apex Agent 消息标准

## 信封

所有 SSE 数据使用：

```json
{
  "event_type": "STREAM_CONTENT",
  "context": {"mode": "react"},
  "messages": []
}
```

- `event_type`：事件类型。
- `context.mode`：默认固定为线协议字符串 `react`，不是可切换执行模式。
- JSON 字段使用 snake_case。
- 字段为空时是否省略由 protocol DTO/Jackson 规则决定；以 Golden File 为准。

## 默认生产事件

### STREAM_CONTENT

模型正文增量。`context.content_id` 标识同一段内容，`messages[*].content` 依次追加。

```json
{"event_type":"STREAM_CONTENT","context":{"content_id":"content-1","mode":"react"},"messages":[{"content":"hello"}]}
```

### HUMAN_INTERVENTION

执行已持久化为 `HUMAN_IN_THE_LOOP`。这是唯一人工介入事件，`messages` 按模型 ToolCall 顺序排列，每项用 `interaction_type` 区分：

- `ASK_HUMAN`：包含 `tool_call_id`、`invocation_id`、`tool_name` 和同一工具调用下的 `questions`；问题支持 TEXT_INPUT、SINGLE_SELECT、MULTI_SELECT、CONFIRM。
- `TOOL_CONFIRMATION`：包含 `confirmation_id`、`tool_call_id`、`invocation_id`、风险、摘要和可编辑字段。

同批存在任意介入时，真实工具和 POST_TOOL_CALL 均未执行。旧的顶层 ASK_HUMAN、TOOL_CONFIRMATION 事件已删除。

```json
{
  "event_type": "HUMAN_INTERVENTION",
  "context": {"mode": "react"},
  "messages": [
    {
      "interaction_type": "ASK_HUMAN",
      "tool_call_id": "call-1",
      "invocation_id": "invocation-1",
      "tool_name": "ask_human",
      "questions": [
        {"input_type": "TEXT_INPUT", "question": "请输入内容", "options": []}
      ]
    },
    {
      "interaction_type": "TOOL_CONFIRMATION",
      "tool_call_id": "call-2",
      "confirmation_id": "confirmation-2",
      "invocation_id": "invocation-2",
      "tool_name": "meeting_tool",
      "tool_display_name": "会议工具",
      "title": "确认执行",
      "risk_level": "MEDIUM",
      "editable": false,
      "confirm_label": "批准",
      "deny_label": "拒绝",
      "display_fields": [],
      "editable_fields": []
    }
  ]
}
```

### INVOCATION_DECLARED / INVOCATION_CHANGE

用于工具/远程调用轨迹。`invocation_id` 是关联键；工具观察者不得通过该通道发布 END 或人工交互事件。

### END

结束当前 SSE 传输。实际载荷精确为：

```json
{"event_type":"END"}
```

END 不包含 `execution_status`、code 或 payload，并由请求级 Once Publisher 保证至多一次。内部 `AgentRunOutcome` 不进入协议。

## 兼容事件

protocol 仍可序列化/反序列化以下事件，前端也保留相应兼容类型或展示；默认 ReAct 链不生产它们：

- STREAM_THINK
- PLAN_DECLARED / PLAN_CHANGE
- TASK_THINK_DECLARED / TASK_THINK_CHANGE
- ARTIFACT_DECLARED / ARTIFACT_CHANGE

保留兼容 DTO 不表示后端仍存在 PlanExecutor、Stage 或计划工具。兼容事件的精确 JSON 见 `protocol/src/test/resources/golden/protocol/*.compat.json`。

## 只读会话状态

`GET /api/sse/sessions/{sessionId}?agentKey=...` 返回 camelCase DTO：

```json
{
  "sessionId": "session-1",
  "agentKey": "default_agent",
  "executionStatus": "HUMAN_IN_THE_LOOP",
  "pendingInteraction": {
    "event_type": "HUMAN_INTERVENTION",
    "context": {},
    "messages": []
  }
}
```

`pendingInteraction` 只允许一个批量 HUMAN_INTERVENTION 或 null，直接由持久化批次映射，不重新执行 core。COMPLETED/FAILED 等非人工态必须为 null。

## 恢复协议

- chat 请求 `type=HUMAN_RESPONSE`，复用原 `sessionId` 与 `agentKey`。
- `humanResponse` 是以 `tool_call_id` 为键的稀疏映射，允许 `{}`。ASK_HUMAN 值含 `answers`；TOOL_CONFIRMATION 值含 `confirmation_id`、`decision`，批准时可含 `updated_args`。
- 未出现的工具键及未出现的问题索引表示未回复；空白字符串和空数组也按未回复处理。默认值由 core 处理对应介入项时即时解析，不由前端补齐。
- 显式提交的未知工具 ID、错误 `interaction_type`、错误确认 ID 或非法答案形态会被拒绝。
- 刷新查询只回显，不自动提交 HUMAN_RESPONSE。

## 错误与并发

- 请求/Header 无效：HTTP 400，无 END。
- session busy：HTTP 409，无 END。
- core 准备失败：HTTP 200 `text/event-stream`，仅一个 END。
- 正常、失败、取消或挂起的已开始传输均由 execution 统一收口 END。

## 变更要求

修改事件时必须同步 protocol DTO/Golden File、生产发送点、前端联合类型/reducer/store、跨端测试和本文。不得只添加 DTO 而没有生产/消费语义，也不得把兼容 DTO 描述为默认能力。
