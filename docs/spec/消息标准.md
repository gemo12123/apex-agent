# 消息标准

> 本文档描述当前后端实际发送的 SSE 事件。前端仍可保留对旧事件类型的兼容定义，但主执行链路不再发送 `STREAM_THINK`。

## 通用格式

所有事件统一使用：

```json
{
  "event_type": "",
  "context": {},
  "messages": []
}
```

## `context` 常用字段

- `mode`：执行模式，取值通常为 `react` 或 `plan-executor`
- `stage_id`：当前计划阶段 ID，仅在 `plan-executor` 下出现
- `executor`：父 Agent 转发子 Agent 调用时标记执行者
- `invocation_id`：工具调用标识，常见于工具执行状态更新和工具确认事件
- `content_id`：同一段流式内容的聚合标识

## 当前主链路会发送的事件

后端出站 SSE 全部经 `util/MessageUtils.java`，主执行链路实际发送的事件只有：

- `STREAM_CONTENT`（`ModelResponseStreamer`）
- `TASK_THINK_CHANGE`（`ModelResponseStreamer`，plan-executor 模式下的主文本通道）
- `PLAN_DECLARED`（`WritePlanTool`）
- `PLAN_CHANGE`（`UpdatePlanTool`）
- `ASK_HUMAN`（`ToolCallProcessor`）
- `TOOL_CONFIRMATION`（`ToolCallProcessor`）
- `END`（`SuperAgentCoordinator`）

条件发送与无生产者的事件：

- `INVOCATION_DECLARED` / `INVOCATION_CHANGE`：主循环不发送，仅当调用远端子 Agent 时由 `tool/handler/impl/InvocationMessageHandler` 把子 Agent 流中的调用事件透传给前端。
- `ARTIFACT_DECLARED` / `ARTIFACT_CHANGE`：消息模型与前端类型齐备，但后端当前没有任何生产者，子 Agent 传来的产物事件也被 `ArtifactMessageHandler` 忽略。

## 事件说明

### `STREAM_CONTENT`

用于输出最终正文或 `react` 模式下的执行结果流。

```json
{
  "event_type": "STREAM_CONTENT",
  "context": {
    "mode": "react",
    "content_id": "c-001"
  },
  "messages": [
    {
      "content": "这是最终答复的正文片段"
    }
  ]
}
```

### `PLAN_DECLARED`

在 `plan-executor` 模式下由 `write_plan_tool` 发出，表示执行计划已经创建。

### `PLAN_CHANGE`

由 `update_plan_tool` 回写阶段状态变化或计划结构调整。

- `change_type`：枚举 `ChangeType` 为 `STATUS_CHANGE`、`CONTENT_APPEND`、`PLAN_CHANGE`；该事件实际只发出 `STATUS_CHANGE` 与 `PLAN_CHANGE`（不存在 `TRY_REPLAN`）
- `operation`：线上只出现 `ADD_STAGE`、`DELETE_STAGE`、`UPDATE_STAGE`；工具入参层的 `START_CURRENT`/`FINISH_CURRENT` 会转成 `change_type=STATUS_CHANGE` 加 `status=RUNNING/COMPLETED`，不落到 `operation` 字段

### `TASK_THINK_CHANGE`

用于把 `plan-executor` 当前阶段内的分析内容追加到任务节点。在 plan-executor 模式且存在未完成阶段时，模型流式输出走本事件而非 `STREAM_CONTENT`，是该模式的主文本通道。载荷字段为 `change_type`（当前只发 `CONTENT_APPEND`）、`task_id`（即当前 `stage_id`）、`status`（`STATUS_CHANGE` 预留，当前不发送）、`content`。

已知缺口：前端 `types/apex.ts` 与 reducer 目前未处理本事件，plan-executor 的思考流在前端被丢弃；补前端消费时需同步联合类型与 reducer。

```json
{
  "event_type": "TASK_THINK_CHANGE",
  "context": {
    "mode": "plan-executor",
    "stage_id": "stage-1",
    "content_id": "c-002"
  },
  "messages": [
    {
      "change_type": "CONTENT_APPEND",
      "task_id": "stage-1",
      "content": "继续补充当前阶段的执行分析"
    }
  ]
}
```

### `INVOCATION_DECLARED` / `INVOCATION_CHANGE`

用于声明和更新工具调用标记，便于前端展示工具执行状态、正文追加和执行者来源。当前仅在子 Agent 调用场景由后端透传，主循环的本地工具执行不发送这两个事件（`ToolExecutionMessageHelper` 中仍是 TODO）。

### `ARTIFACT_DECLARED` / `ARTIFACT_CHANGE`

用于声明和追加结构化产物，既支持阶段级产物（`scope=STAGE`），也支持全局产物（`scope=GLOBAL`）。当前后端没有生产者，前端的 `stage.artifacts` 与 `globalArtifacts` 在生产环境恒为空；协议与前端消费逻辑保留，供后续接入。

### `ASK_HUMAN`

当模型需要用户补充信息时发送。前端收集输入后，以 `RequestType.HUMAN_RESPONSE` 恢复会话。

### `TOOL_CONFIRMATION`

当工具在真正执行前需要用户确认或允许用户修改可编辑参数时发送。前端收集输入后，同样以 `RequestType.HUMAN_RESPONSE` 恢复会话。

```json
{
  "event_type": "TOOL_CONFIRMATION",
  "context": {
    "mode": "react",
    "executor": "functions.shell_command",
    "invocation_id": "inv-001"
  },
  "messages": [
    {
      "confirmation_id": "confirm-001",
      "tool_call_id": "call-001",
      "invocation_id": "inv-001",
      "tool_name": "functions.shell_command",
      "tool_display_name": "PowerShell 7",
      "title": "确认执行命令",
      "description": "该命令将访问工作区中的项目文件。",
      "risk_level": "MEDIUM",
      "editable": true,
      "confirm_label": "确认执行",
      "deny_label": "取消",
      "display_fields": [],
      "editable_fields": []
    }
  ]
}
```

恢复约定：

- 前端通过 `RequestType.HUMAN_RESPONSE` 恢复会话
- `humanResponse` 以 `tool_call_id` 作为键组织提交结果
- 对应值至少包含 `decision`，取值为 `APPROVE` 或 `DENY`
- 如果事件允许编辑参数，可额外提交 `updated_args`

### `END`

每轮 SSE 由 `SuperAgentCoordinator` 在 `finally` 中补发 `END`，用于通知前端关闭本轮流。当前实际线上载荷就是：

```json
{"event_type":"END"}
```

`context.execution_status`（`COMPLETED`/`FAILED`/`HUMAN_IN_THE_LOOP`）是协议预留字段：前端已实现按它收口状态，但后端目前从不写入，前端始终走“缺失字段”兼容分支（按待处理 prompt/confirmation 推断）。

## 兼容事件

- `STREAM_THINK`：兼容旧协议保留的事件模型，前端 reducer 仍处理，但后端已无生产者
- `TASK_THINK_DECLARED`：事件模型仍存在，后端无生产者，前端也未消费
