# 清理与整体验收详细设计

## 设计定位

清理阶段只删除已有目标实现和验证证据覆盖的旧代码。它不是继续重构或顺手改名的阶段；每项删除必须能追溯到新模块类型、测试和切换门槛。

## CLEAN-01 删除 PlanExecutor、Stage 与执行模式

### 实现目标

删除后端全部执行模式、Plan、Stage、计划工具、模式Prompt和运行生产逻辑，使唯一循环成为事实；protocol兼容 DTO继续存在，`react` 只在事件工厂中是线协议字符串。

### 涉及模块/类

删除目标：

- `constant/ModeEnum`、PlanOperation/TaskStatus等仅计划运行使用常量。
- `domain/Plan`、`domain/Stage`、`SuperAgentContext.Stage/executionMode/currentStageId/plan`。
- `StageToolResolver`、`StageToolPlan`、`StagePromptBuilder`及模式分支。
- `ToolInterceptor`的模式/计划守卫。
- `WritePlanTool`、`UpdatePlanTool`。
- PlanExecutor Prompt资源、配置字段、数据库残留、TASK_THINK运行生产者。

保留：protocol PLAN/TASK/STREAM_THINK DTO及序列化测试；不修改前端。

### 核心流程

1. 用新core/runtime/platform覆盖矩阵证明旧入口已不运行。
2. 按“生产引用 -> 配置/资源 -> 测试 -> 依赖”顺序删除。
3. 全仓限定当前源码搜索计划运行词，区分历史文档/兼容 DTO。
4. 运行父测试和协议Golden File。

### 接口和数据结构

目标 common/core 不存在 Mode/Stage/Plan类型。EventContextFactory直接写 `"mode":"react"`，不能通过 enum或Agent状态取得。

兼容 DTO的常量仍位于protocol `AgentEventType`，并标注默认不生产。

### 关键实现逻辑

- 删除工具时同步从默认registry/AgentDefinition/YAML和Prompt提及中移除。
- 删除TASK_THINK生产逻辑不能删除SubAgent parser对兼容事件的可反序列化能力；默认处理可NoOp/忽略，但protocol仍识别。
- 数据库目标schema从未创建plan字段；清理检查migration而非对新库执行DROP旧表。
- 历史设计文档保留，不做机械全仓词语清零；检查范围限定生产源码、目标测试、运行资源、当前态文档。

### 异常处理

- 发现新链路仍依赖任一计划类型则停止删除，回到责任任务补替代，不能用临时Adapter延长。
- Golden File兼容 DTO失败时修protocol，不恢复生产者。

### 测试方案

- `rg` 限定七个代码模块的标准 `src`；memory archive 单独做“不被 source/resource/依赖引用”检查，不把其中历史类名计入生产源码清理结果。兼容允许名单只有 protocol DTO/测试。
- 唯一ReactLoop架构测试、无Mode/Stage class字节码。
- protocol兼容事件round-trip、默认运行事件计数为0。
- 父工程全量测试。

### 架构符合性

删除后core只有Session/Turn/Iteration/ReAct，满足原始需求最关键的模式收敛。

## CLEAN-02 完成 ApexAgent 重命名与 legacy/Fastjson 清理

### 实现目标

删除legacy、旧SuperAgent族、重复Hook Runtime、临时Adapter和Fastjson，最终只保留八模块与ApexAgent命名。

### 涉及模块/类

- 删除 legacy module及其 `SuperAgent*`、旧context/factory/coordinator/session service。
- 删除 `AgentHookRuntime/DefaultAgentHookRuntime/DefaultAgentLifecycleHookRuntime`旧实现和死Adapter。
- 删除 Fastjson依赖/import；当前明确的生产调用点是 `ToolCallProcessor`、`SubAgentToolCallback`，迁移后应已由common JsonUtils替代。
- 更新目标JavaDoc、日志、异常、Prompt和测试类名。

### 核心流程

1. 证明G5 platform已接管且无目标模块/测试依赖legacy。
2. 删除legacy源码/POM，父modules移除legacy。
3. 删除迁移Adapter和过期豁免。
4. 搜索并清理目标当前态中的SuperAgent/Fastjson/旧Hook。
5. 运行FND-03B和全量测试。

### 接口和数据结构

最终命名映射：ApexAgent、ApexAgentContext、ApexAgentFactory、ApexAgentRuntime、ApexAgentExecution、ApexAgentCoordinator、ApexAgentPlatformConfiguration。

不修改外部 `/api/sse/*`、sessionId、agentKey、event_type或仓库目录 `apex-agent`。

### 关键实现逻辑

- 删除按文件迁移矩阵逐项确认“目标位置、目标测试、最后调用点”。
- 只有platform配置Spring Boot repackage；父/其他模块无execution。
- dependency tree检查传递Fastjson，不仅源码import。
- `SuperAgent`可在历史文档中出现；生产/当前态文档和测试类名不能出现。
- legacy删除后父POM临时JUnit4/旧依赖一并清理，不让它们泄漏目标模块。
- 对每个目标模块运行 dependency analyze；直接使用的项目模块必须直接声明，protocol 不得通过测试依赖回指 common。
- 扫描 kit 源码/artifact 不存在 `StandardToolResultFactory` 或拒绝/强制结束/取消固定结果工厂；三段文案的生产所有权只在 core `ToolResultFactory`。

### 异常处理

- 文件仍被编译/测试引用时不使用排除规则遮盖，回到对应迁移任务。
- 第三方传递Fastjson必须exclusion并验证该库运行不需要，或替换依赖；不能只ban direct。

### 测试方案

- 父modules精确八项、目录无legacy。
- `rg`生产源码无 `class SuperAgent`、Fastjson import、旧Hook runtime。
- Maven dependency tree无Fastjson/fastjson2、目标外legacy artifact。
- 父test/package，只有platform生成可执行Boot jar。

### 架构符合性

清理后物理源码树、命名和依赖图与目标架构完全一致，不保留双实现或迁移逃生通道。

## CLEAN-03 更新当前态文档并执行全量交付验收

### 实现目标

更新当前态文档并生成可复现验收证据，证明八模块目录、七个代码模块、核心行为、恢复、runtime 独立性、platform 协议/数据库、memory 归档隔离和前端刷新回显全部达到目标。

### 涉及模块/类

- `docs/reference/后端开发.md`、`跨端契约.md`、`验证与交付.md`。
- `docs/overview/项目概览.md`、`快速开始.md`、`架构与执行流程.md`。
- `docs/spec/消息标准.md`、发布说明、部署/回滚说明。
- 父POM、全模块测试报告、前端验证。

### 核心流程

1. 先从最终源码生成模块/入口/配置/事件事实，再更新当前态文档。
2. 运行七个代码模块单测/架构测试、core Fake 行为、runtime 集成、platform PostgreSQL/HTTP/SSE；memory 只执行 POM/source root/MANIFEST/发布物静态检查，不运行测试。
3. 运行前端三项验证和源码diff。
4. 生成需求-设计-任务-实现-测试覆盖矩阵。
5. 记录未验证项、默认能力变化、单实例限制和回滚步骤。

### 接口和数据结构

验收矩阵字段：`requirementId`、`decisionId`、`taskId`、`productionTypes`、`tests`、`command`、`result`、`evidencePath`、`notes`。

发布说明至少列：PlanExecutor删除、ApexAgent命名、配置不兼容迁移、PostgreSQL新库、memory默认关闭、single replica、snapshot仅1.0.0。

### 关键实现逻辑

- 当前态消息标准改写为目标实际生产事件，但保留兼容 DTO说明；不能继续描述legacy TASK_THINK生产。
- END仍说明无execution_status且一次；不要把内部AgentRunOutcome写成协议字段。
- 快速开始分别提供runtime-only与platform PostgreSQL两条路径。
- 回滚只能回到legacy发布版本/旧库，不能让新platform读取旧MySQL或让旧版本读取新TEXT快照。
- 前端只保留 Q-14 的状态 DTO、查询 API、session 定位与刷新回显最小改动；任何无关格式化或功能变化都需回退后重跑。
- Spring AI 最终版本必须能从 RUN-02 对齐报告追溯到 FND-01 基线和具体触发证据；禁止只在最终 POM 留下无法解释的版本数字。

### 异常处理

- 关键门槛失败即阻塞交付；未执行的Docker/前端检查列未验证，不能按通过。
- 发现文档与源码冲突先修当前态文档或实现，再生成最终报告。
- R-02、R-04～R-10、R-12、R-13、R-15 已按 2026-07-31/2026-08-01 补充决策关闭；R-21/R-22 已按依赖与所有权边界校正。R-09 的只读状态查询和前端回显或 R-13 的依赖对齐证据未实现/未验收时，CLEAN-03 不得签收。

### 测试方案

- `mvn -f apex-agent/pom.xml test` 和最终架构verify。
- core 11生命周期/ReAct/压缩/工具/恢复五分支，以及“只有AGENT_BUILD改定义”和不可用新/旧绑定分流。
- runtime无IoC、lease、Once、内存别名、资源关闭、外部集成不可用状态与历史绑定不可执行；RUNNING cancel/close 非阻塞，模型/MCP/HTTP 主动取消，finally 才释放 lease，runtime close 无超时/grace period。
- Maven 模块直接依赖与契约图一致、used-but-undeclared 为零，protocol/common 消费测试无 reactor 回边；Spring AI convergence 无豁免且对齐报告完整；core 唯一 ToolResult 工厂、kit 无重复实现。
- platform Testcontainers、HTTP/SSE、400/409、core准备失败仅END、重启恢复、TEXT长内容。
- memory POM/MANIFEST/source-resource 隔离检查；明确不运行 memory 行为测试。
- 前端 `test:run`、`typecheck`、`build`；diff 审查确认只增加状态 DTO、查询 API、session 定位与刷新回显，并有两类 HITL 回归测试。

### 架构符合性

最终验收把模块结构、核心不变量、质量属性和外部兼容同时转成证据，是删除legacy并交付目标架构的最后门槛。
