# 跨模块契约详细设计

> 本文是 50 个任务共享的编码契约。模块分册只描述各任务对这些契约的实现责任。

## 1. 模块与包边界

| Maven 模块 | Java 包根 | 允许的项目模块依赖 | 禁止内容 |
| --- | --- | --- | --- |
| protocol | `org.gemo.apex.protocol` | 无 | core 上下文、Spring AI、Servlet、SSE、ORM |
| common | `org.gemo.apex.common` | protocol | Spring、Spring AI、Servlet、ORM、数据库驱动 |
| core-extension | `org.gemo.apex.extension` | protocol、common | 非 interface 顶级类型、默认实现、Spring 注解 |
| core | `org.gemo.apex.core` | protocol、common、core-extension | Spring IoC、Servlet、SSE、数据库、MCP 客户端 |
| kit | `org.gemo.apex.kit` | protocol、common、core-extension | core 实现、注册表、状态机、Spring Bean |
| runtime | `org.gemo.apex.runtime` | protocol、common、core-extension、core、kit | platform、memory、Spring IoC 必需条件 |
| platform | `org.gemo.apex.platform` | protocol、common、core-extension、runtime | core 语义的重复实现、私有 session 锁表 |
| memory | 无标准 Java 包（`packaging=pom`） | 无 | 标准 `src/main`/`src/test`、项目依赖、archive 被其他模块扫描或打包 |

表中列的是标准生产/测试源码的真实直接项目依赖，不是最短传递边。模块 POM 必须直接声明源码或测试字节码直接引用的项目模块；例如 core-extension 的 `AgentEventPublisher` 引用 protocol `AgentMessage`，所以同时直接依赖 protocol 与 common。memory 的非标准 archive 目录只保存历史材料，其中旧 import 不参与 Maven 依赖图。父 POM 用 dependencyManagement 固定版本，不通过把所有库放进父 dependencies 达成“可见”。七个代码模块 `maven-dependency-plugin:analyze` 的 used-but-undeclared 结果必须为零。

## 2. common 核心数据结构

### 2.1 Agent 定义

建议以 record 为主，构造时统一 `List.copyOf`、`Set.copyOf`、`Map.copyOf`：

```java
public record AgentDefinition(
        String schemaVersion,
        AgentMetadata metadata,
        PromptDefinition prompt,
        MessageCompressionDefinition messageCompression,
        ToolSetDefinition tools,
        Set<String> enabledSkills,
        Map<String, SubAgentDefinition> subAgents,
        Map<HookPoint, List<HookBinding>> hooks) {}

public record AgentMetadata(String agentKey, String name, String description) {}

public record ToolSetDefinition(
        Set<String> availableTools,
        Set<String> defaultEnabledTools) {}

public record HookBinding(
        String id,
        String name,
        int order,
        boolean enabled,
        List<String> tools,
        Map<String, Object> options) {}
```

`AgentDefinitionDraft` 是 common 中唯一可变的构造草稿；它只暴露受控操作，不把内部集合直接交给 Hook。`AgentDefinitionOperation` 使用 `AddAvailableTool`、`RemoveAvailableTool`、`ReplacePrompt`、`AddHookBinding`、`RemoveHookBinding` 等分型 record，且只能出现在 `AgentBuildHookResult`。其他生命周期结果类型不得引用 `AgentDefinitionOperation` 或 Hook Binding Patch。AGENT_BUILD 的当前分发链在进入生命周期时拍快照；Hook 对 `agent-build` Binding 的修改不回头重跑当前链，只进入最终定义快照。

运行用 `AgentDefinitionSnapshot` 与持久化用 `AgentDefinitionRecoverySnapshot` 分开：

- `AgentDefinitionSnapshot` 含本 Turn 运行所需的完整最终定义，包括 `defaultEnabledTools`。
- `AgentDefinitionRecoverySnapshot` 不含 `defaultEnabledTools`，只含 Prompt 文本、压缩参数、availableTools、enabledSkills、SubAgent 稳定定义、Hook Binding 和 `schemaVersion`。
- NEW 首 Turn初始化完成后立刻生成 recovery snapshot；HUMAN_RESPONSE 只能读取 recovery snapshot，不能重新访问 Provider。

### 2.2 Session、Turn、Iteration

```java
public record SessionSnapshot(

        Set<String> enabledTools,

public record HistoricalToolBinding(

        String sourceId,
        String reasonCode,
        Instant disabledTime) {}

public enum ToolOrigin { KIT, LOCAL, SKILL, MCP, SUB_AGENT }

public record UnavailableToolSource(
        ToolOrigin origin,
        String sourceId,
        String stableNamePrefix,
        String reasonCode,
        Instant observedAt) {}

public record ToolAvailabilitySnapshot(
        Set<String> unavailableToolNames,
        List<UnavailableToolSource> unavailableSources) {}
```

`historicalToolBindings` 只记录曾在该 session 的有效定义中存在、后来因 MCP/SubAgent 不可用而退出执行面的绑定。以 `(toolName, origin, sourceId)` 去重，首次 `disabledTime` 不覆盖；它不属于 `enabledTools`，不得用于构造 ToolCatalog、模型工具列表或执行授权。历史对话中的 ToolCall/ToolResult 原样保留，当前前端继续通过既有消息历史展示；本期不增加绑定历史 HTTP/SSE 字段。

状态集合：

| 层级 | 状态 | 进入条件 |
| --- | --- | --- |
| Session | `IN_PROGRESS` | NEW 已建立 Turn，正在运行 |
| Session | `HUMAN_IN_THE_LOOP` | 当前 ToolCall 挂起成功保存 |
| Session | `COMPLETED` | 当前 Turn 正常或 END_TURN 收口 |
| Session | `FAILED` | 模型、存储、核心契约或不可恢复基础设施异常 |
| Session | `CANCELLED` | 当前请求执行收到取消命令并在取消检查点完成收口；后续合法 NEW 可开启新 Turn |
| Turn | `IN_PROGRESS` | NEW 创建 |
| Turn | `SUSPENDED` | 人工介入保存成功 |
| Turn | `COMPLETED` | 无工具最终文本或正常工具循环完成 |
| Turn | `ENDED_BY_HOOK` | 合法 Hook END_TURN |
| Turn | `FAILED` | 本 Turn 核心失败 |
| Turn | `CANCELLED` | 当前执行响应取消命令退出 |
| Iteration | `IN_PROGRESS` | 即将进行一次业务模型调用 |
| Iteration | `SUSPENDED` | 该模型响应的 ToolCall 等待人工输入 |
| Iteration | `COMPLETED` | 模型响应及其全部 ToolCall 已完整处理 |
| Iteration | `FAILED` | 模型或持久化导致本 Iteration 失败 |
| Iteration | `CANCELLED` | 当前模型/工具调用响应取消命令退出 |
| ToolCall execution | `CANCELLED` | Assistant ToolCall 已持久化后，当前或剩余调用因请求取消而不再完成 |

目标态删除 `SKIPPED`、Stage、Plan 和 Mode 状态。SessionSnapshot 只嵌套当前活动 Turn/Iteration；历史对话由 ConversationRepository 保存。

`entryId` 在第一次写 Repository 前生成并在重试中保持不变。ToolCall 的 `ordinal` 只表示模型响应中的顺序，不作为恢复定位键；恢复只用 `toolCallId`。

### 2.4 人工介入结构

```java
public record SuspendedToolCall(
        String sessionId,
        long turnNo,
        int iterationNo,
        String toolCallId,
        String invocationId,
        String toolName,
        Map<String, Object> resolvedArguments,
        HumanInterventionRequest intervention,
```

`HumanInterventionRequest` 是 sealed interface，只有 `QuestionInterventionRequest` 和 `ToolConfirmationInterventionRequest`。确认对象保存 `confirmationId`、展示 DTO、允许编辑键；QUESTION 保存问题列表及 toolCallId。挂起对象不保存 ToolCall 数组 index、Publisher、enabledTools、定义快照或其他生命周期 Hook 历史。

- `QuestionSubmission(toolCallId, answers)`；兼容前端 `{interaction_type:"ASK_HUMAN", answers:{...}}`。
- `ToolConfirmationSubmission(toolCallId, confirmationId, decision, updatedArguments)`。

解析完成后不再在 core 传播未校验 Map。

## 3. core-extension 接口

所有以下类型都位于独立 `.java` 文件且顶级类型为 interface。接口使用的 descriptor、命令和结果 record 位于 common。端口组合时允许引用同模块的其他 interface，例如 `ToolProvider` 返回 `AgentTool`、`AgentTool` 接收 `ToolExecutionObserver`；这不允许引入任何同模块实现或实体。

```java
public interface AgentDefinitionProvider {
    AgentDefinition load(String agentKey);
    List<AgentMetadata> listAgents();
}

public interface ModelGateway {
    ModelResponse stream(ModelRequest request, ModelStreamObserver observer);
}

public interface ModelStreamObserver {
    void onChunk(ModelStreamChunk chunk);
    CancellationToken cancellationToken();
}

public interface AgentTool {
    ToolDefinition definition();
    ToolResult execute(ToolCall call,
                       ToolExecutionContext context,
                       ToolExecutionObserver observer);
}

public interface ToolExecutionObserver {
    void onEvent(AgentMessage event);
    CancellationToken cancellationToken();
}

public interface ToolProvider {
    List<AgentTool> loadTools(AgentDefinition definition);
    List<AgentTool> loadTools(AgentDefinitionRecoverySnapshot definition);
}

public interface ToolAvailabilityProvider {
    ToolAvailabilitySnapshot current();
}

public interface LifecycleHook<C extends HookContextView,
                               R extends LifecycleHookResult> {
    HookTypeDescriptor descriptor();
    R apply(C context);
}

public interface HookResolver {
    LifecycleHook<?, ?> resolve(HookPoint point, String name);
}

public interface AgentEventPublisher {
    void publish(AgentMessage message);
}

public interface AgentEventPublisherFactory {
    AgentEventPublisher create(AgentExecutionDescriptor execution);
}

public interface SessionRepository {
    Optional<SessionSnapshot> load(String sessionId);
    void save(SessionSnapshot snapshot);
}

public interface ConversationRepository {
    void append(List<AgentMessageEntry> entries);
    List<AgentMessageEntry> load(ConversationQuery query);
    void compact(ConversationCompactionCommit commit);
}

public interface SkillProvider {
    List<SkillDefinition> loadSkills();
}

public interface SkillActivator {
    SkillActivationResult activate(String skillName,
                                   Set<String> enabledSkills,
                                   Set<String> activatedSkills);
}
```

`ToolProvider` 的两个重载避免“只有冻结快照才能解析工具、但冻结前又必须校验工具”的循环：NEW 在 AGENT_BUILD 后把草稿物化为尚未冻结的 `AgentDefinition` 候选并解析工具；恢复直接按 recovery snapshot 解析。core 把返回列表索引为请求级 ToolCatalog。

`ToolAvailabilityProvider` 返回上述不可变 `ToolAvailabilitySnapshot`。ToolProvider 在解析定义时若发现新的 MCP/SubAgent 初始化失败，必须先原子更新快照再返回健康工具，避免 Assembler 看到“工具缺失但无原因”的中间态。`stableNamePrefix` 必须来自工具命名规则，不能按任意字符串包含关系匹配。

Assembler 按下列规则消费该快照：

1. 新 session 的候选定义或本次 AGENT_BUILD 新增的绑定命中不可用工具/来源时，抛 `UnavailableToolBindingException`，不生成部分定义快照。
2. 已有 session 上一版 `activeDefinition.availableTools` 已含该绑定时，将其追加到 `historicalToolBindings`，从本次有效 `availableTools`、`defaultEnabledTools`、`enabledTools` 与 ToolCatalog 移除后继续；原快照和对话记录不原地修改。
3. 普通注册缺失、重命名或来源不明仍按配置漂移失败，不能伪装成初始化故障。
4. 健康状态恢复只允许后续新 session/显式配置再次绑定；既有 session 的历史绑定不得自动回填 `enabledTools`。

`SkillActivationResult` 位于 common，包含 instructions 和新的不可变 activatedSkills 集合。其他接口：`ConversationWindowManager`、`ConversationCompactionPolicy`、`ConversationCompactor`、`IdGenerator`、`TimeProvider`。

## 4. core 入口与运行对象

core 提供两个稳定入口：

```java
public final class ApexAgentFactory {
    public ApexAgent createNew(AgentRequest request, AgentPorts ports);
    public ApexAgent createResumed(HumanResponseCommand command, AgentPorts ports);
}

public final class ApexAgent {
    public AgentRunOutcome run();
    public AgentRunOutcome cancelBeforeRun();
}
```

`AgentPorts` 是 core 内的不可变装配对象，引用 core-extension 端口和本请求 `AgentEventPublisher`，不进入持久化。`ApexAgentContext` 只持有可变运行状态和 `AgentPorts`；它不暴露给 Hook，也不含 Spring 类型。

`createNew` 的固定顺序：

```text
load optional session
  -> validate user/agent/session state
  -> AgentDefinitionAssembler.assemble
  -> reject unavailable new bindings or migrate existing bindings to history
  -> create or increment Turn
  -> initialize/retain session tool and Skill state
  -> append user message idempotently
  -> save SessionSnapshot
  -> return ApexAgent
```

`createResumed` 的固定顺序：

```text
load required SessionSnapshot
  -> validate user/agent/HUMAN_IN_THE_LOOP
  -> validate and parse submission
  -> rebuild definition from recovery snapshot
  -> classify unavailable old binding as historical/non-executable
  -> resolve Hook/Tool by stable name
  -> locate ToolCall by toolCallId
  -> return ApexAgent positioned at remaining PRE_TOOL_CALL chain
```

## 5. 生命周期契约

### 5.1 分发顺序

Hook Binding 按 `(order ASC, id ASC)` 排序。`id` 在同一 HookPoint 内唯一；同 order 用 id 保证确定性。disabled Binding 不分发，也不进入已执行列表。

生命周期结果族：

| HookPoint | Context | Result interface | 合法动作 |
| --- | --- | --- | --- |
| AGENT_BUILD | `AgentBuildContext` | `AgentBuildHookResult` | Continue |
| TURN_START | `TurnStartContext` | `LoopHookResult` | Continue、EndTurn |
| ITERATION_START | `IterationStartContext` | `LoopHookResult` | Continue、EndTurn |
| PRE_MESSAGE_COMPRESSION | `PreMessageCompressionContext` | `PreMessageCompressionHookResult` | Continue、EndTurn |
| POST_MESSAGE_COMPRESSION | `PostMessageCompressionContext` | `PostMessageCompressionHookResult` | Continue、EndTurn |
| PRE_MODEL_CALL | `PreModelCallContext` | `PreModelCallHookResult` | Continue、EndTurn |
| POST_MODEL_CALL | `PostModelCallContext` | `PostModelCallHookResult` | Continue、EndTurn |
| PRE_TOOL_CALL | `PreToolCallContext` | `PreToolCallHookResult` | Continue、Block、Return、Intervention、EndTurn |
| POST_TOOL_CALL | `PostToolCallContext` | `PostToolCallHookResult` | Continue、EndTurn |
| ITERATION_END | `IterationEndContext` | `LoopHookResult` | Continue、EndTurn |
| TURN_END | `TurnEndContext` | `TurnEndHookResult` | Continue |

### 5.2 原子应用

每个 Hook 按以下模板执行：

1. 从当前运行状态创建只读 Context 快照。
2. 调用 Hook，捕获普通执行异常。
3. 校验返回对象非空、结果族匹配、动作合法、Patch 完整、工具变更不越界。
4. 在临时副本上应用全部 operation。
5. 校验临时副本整体不变量。
6. 一次性替换运行状态引用。

第 2 步异常记录 warn 后继续；第 3～5 步属于契约非法，抛出 `HookContractException` 并终止当前执行，不得按普通 Hook 异常吞掉。

只有 AGENT_BUILD 的原子应用目标是 `AgentDefinitionDraft`。其余十个生命周期的临时副本只能覆盖消息、session `enabledTools`、当前模型请求/响应、工具调用/结果或压缩对象；任何定义/Hook Binding 操作都属于第 3 步契约非法。

## 6. ReAct 与恢复状态机

### 6.1 NEW/ReAct

```text
TURN_START
while iterationNo <= maxIterations:
  create Iteration
  ITERATION_START
  prepare base request
  shouldCompact exactly once
  [PRE_COMPRESSION -> compact -> POST_COMPRESSION -> persist]
  append final-iteration instruction when applicable
  PRE_MODEL_CALL
  hard-limit validation
  ModelGateway.stream
  POST_MODEL_CALL
  append assistant message
  if no ToolCall: ITERATION_END -> TURN_END -> complete
  if last Iteration still has ToolCall: synthesize forced ToolResults -> end
  process ToolCalls in ordinal order
  ITERATION_END
```

`maxIterations` 是允许的业务模型调用总数。iterationNo 建议从 1 开始，最后一次条件为 `iterationNo == maxIterations`，避免 0/1 基准混用。

### 6.2 HUMAN_RESPONSE

恢复不执行 AGENT_BUILD、TURN_START、ITERATION_START、压缩生命周期、模型生命周期或模型调用。它从当前 ToolCall 的剩余 PRE_TOOL_CALL Binding 开始：

```text
parse submission
  -> skip executed hook IDs
  -> dispatch remaining PRE hooks
  -> suspend again | end turn | block | direct result | execute
  -> POST_TOOL_CALL when a ToolResult exists
  -> append result + save snapshot
  -> continue remaining ToolCalls
  -> ITERATION_END
  -> next Iteration enters the normal compression gate
```

确认拒绝在进入剩余 PRE Hook 前直接映射为 ReturnToolResult，因此不执行剩余 PRE Hook；结果文本固定“用户拒绝执行”。拒绝与 END_TURN 强制结束均由 core 内部唯一 `ToolResultFactory` 按原 toolCallId/name 生成，metadata 为空；kit 只生成确认介入请求，不拥有或复制这两类状态机结果。

## 7. 存储一致性与幂等

本期不做跨 Repository 原子事务，但接口必须支持确定性重试：

- `AgentMessageEntry.entryId` 在 core 生成，ConversationRepository 按 entryId 幂等追加。
- PostgreSQL 同时保留 `(session_id, sort_no)` 唯一约束。相同 entryId/内容重复写视为成功；同 sortNo 不同 entryId 或内容视为冲突。
- `ConversationCompactionCommit` 含稳定 `compactionId`、来源边界和最终摘要；重复提交同一对象视为成功。
- SessionRepository 保存完整快照；同一 lease 内按调用顺序写，不提供跨实例并发承诺。

固定提交顺序：

| 场景 | 顺序 | 任一步失败后的行为 |
| --- | --- | --- |
| 新 Turn | append user -> save session | 停止，不调用 Hook/模型；重试复用 entryId |
| 人工介入 | save session -> publish interaction -> END | save 失败不发交互事件 |
| 压缩 | compact conversation -> save session -> PRE_MODEL | 停止模型；重试复用 compactionId |
| ToolResult | append result -> save session -> next ToolCall | 停止后序调用；重试复用 entryId |
| 模型失败 | mark three states -> best-effort save session -> END | 原始模型异常为主异常，保存失败作为 suppressed/log |

## 8. 事件发布契约

- core 只构造 protocol `AgentMessage` 并调用 `AgentEventPublisher`。
- 每个 NEW/HUMAN_RESPONSE 都由 runtime 创建 `OnceAgentEventPublisher`。
- `OnceAgentEventPublisher` 状态为 OPEN/ENDED。首个 END 原子切到 ENDED 后转发；后续 END 忽略；ENDED 后的非 END 发布抛 `EventStreamClosedException`。
- Publisher 发送失败抛 `AgentEventPublishException` 并由 execution 的 `RuntimeCancellationSource` 发出取消命令。模型、HTTP、MCP 和工具适配器必须把自身可取消句柄注册到同一 token；不能只轮询 `isCancellationRequested()`。
- ToolExecutionObserver 只允许 `INVOCATION_DECLARED`、`INVOCATION_CHANGE`；其他事件抛 `IllegalToolEventException`。
- platform 的 emitter 完成由 platform 负责；END 幂等由 runtime 负责，两者不共享状态。
- core 同步构造/恢复准备失败发生在业务事件发布前；runtime 发布唯一精确 END、释放 lease并抛 `AgentPreparationException(endPublished=true)`，platform 只 complete并返回该 emitter。参数400与busy409不走此分支且不发END。

## 9. runtime 执行与 lease

```java
public final class ApexAgentExecution implements AutoCloseable {
    public AgentRunOutcome run();
    public boolean cancel();
    public boolean cancelBeforeStart();
    public void close();
}
```

内部状态：PREPARED、RUNNING、CANCEL_REQUESTED、TERMINATED。`cancel()` 是非阻塞命令：PREPARED 时先 CAS 为 CANCEL_REQUESTED，阻止并发 run，再发出 token 取消、调用 core `ApexAgent.cancelBeforeRun()` 把已同步创建的 Session/Turn 记为 CANCELLED 并保存，随后 terminate；RUNNING 时 CAS 为 CANCEL_REQUESTED、执行全部已注册取消 command 后返回，不等待调用完成、不提前释放 lease；重复调用返回 false。`cancelBeforeStart()` 只接受 PREPARED，供线程池拒绝路径显式使用。`close()` 委托 `cancel()`，因此 RUNNING 也会收到取消命令。run/cancel 最终出口调用同一个 `terminateOnce`：先原子把状态切为 TERMINATED，再依次确保 END、关闭请求资源、释放 lease、从 runtime 活动表注销。这样 emitter completion callback 在 END/complete 期间回调 `cancel()` 只得到 false，不会把正常完成反向改成取消。

core 在 Hook、模型、工具和持久化边界前后调用 `throwIfCancellationRequested()`；捕获取消后不再进入新外部调用，把当前活动 Iteration/Turn/Session 标记 `CANCELLED` 并保存，然后返回。若取消发生在 Assistant ToolCall 已追加之后，CORE-06 必须为当前及所有未完成调用按原 ID/name 追加内容固定为“请求已取消，工具未执行完成”的 ToolResult，metadata 为空、不运行 PRE/POST Hook或真实工具；取消结果按 ordinal 一次批量 append，随后一次 save 同时提交 ToolExecutionStatus 与三层 CANCELLED。这只用于保持未来模型历史的一一配对，不继续当前 Turn 的模型调用。若模型流阶段尚未追加 Assistant entry，则不创建该结果。默认适配器收到命令后必须主动调用其底层取消能力：模型 subscription `dispose`、HTTP future/body stream `cancel/close`、MCP call handle `cancel`。本期不设置取消超时、grace period，也不承诺不合作的自定义工具在有限时间内退出；lease 只能由实际执行线程的 finally 释放。

`cancel()` 返回值只表示本请求是否首次发出取消命令，不承诺最终状态一定为 CANCELLED。若 core 在命令前已提交 COMPLETED/FAILED/HUMAN_IN_THE_LOOP 等业务终态，迟到取消不重写该终态；若 core 在终态前观察到 token，则进入 CANCELLED。`CANCELLED` 不永久封死 session：lease 释放后，后续 NEW 可创建递增的新 Turn 并把 Session 重新置 `IN_PROGRESS`；HUMAN_RESPONSE 只能用于 `HUMAN_IN_THE_LOOP`，不得恢复已取消 Turn。

进程内协调器使用 `ConcurrentHashMap.compute` 原子获取和释放，LockEntry 含 owner token。获取时已有 entry 立即抛 `SessionBusyException`；释放必须在同一次 compute 中校验 owner 并删除，禁止“先置空再 remove”造成新持有者条目被旧 lease 删除。

## 10. 异常分类

| 异常 | 所属模块 | 处理 |
| --- | --- | --- |
| `InvalidAgentDefinitionException` | core | 构造失败；不创建部分 Turn |
| `UnavailableToolBindingException` | core | 禁止新活动绑定；不创建部分定义/Turn |
| `SessionNotFoundException` | core | HUMAN_RESPONSE 拒绝 |
| `SessionOwnershipException` | core | 拒绝，不修改快照 |
| `SessionStateException` | core | NEW/恢复状态不合法 |
| `HumanResponseValidationException` | core | 拒绝，不执行 Hook/工具 |
| `HookContractException` | core | 执行失败；普通 Hook 抛错不使用此类 |
| `ModelInvocationException` | runtime adapter/core boundary | 三层 FAILED，立即结束 |
| `ToolExecutionException` | runtime adapter | 转换为当前 ToolResult，Turn 继续 |
| `CancellationRequestedException` | common，由 core/runtime 使用 | 不按模型/工具失败处理；三层转 CANCELLED，已追加 Assistant ToolCall 时由 core 补标准取消结果，随后由 execution finally 收口 |
| `RepositoryException` | adapter | 停止后续动作并传播 |
| `SessionBusyException` | runtime | platform 同步映射 HTTP 409 |
| `AgentPreparationException(endPublished=true)` | runtime | platform complete并返回HTTP 200的仅END SSE |
| `UnsupportedSnapshotVersionException` | common adapter | 明确拒绝读取，不尝试升级 |
| `AgentEventPublishException` | publisher adapter | 发出当前 execution 的取消命令；实际退出的 finally 发布幂等 END、关闭请求资源并释放 lease |

请求级 Publisher 已绑定后，上表中发生于 `ApexAgentFactory.createNew/createResumed` 的同步 core 异常统一由 runtime 收口为 `AgentPreparationException(endPublished=true)`；其内部类型只用于日志和测试，不改变 SSE。core 不产生新的 SSE 错误事件。END 仍精确序列化为 `{"event_type":"END"}`。

## 11. PostgreSQL 标量与 TEXT 映射

`apex_agent_session` 建议使用：

- `session_id VARCHAR(128) PRIMARY KEY`
- `user_id VARCHAR(128) NOT NULL`
- `agent_key VARCHAR(128) NOT NULL`
- `status VARCHAR(32) NOT NULL`
- `current_turn_no BIGINT NOT NULL`
- `agent_definition_snapshot TEXT NOT NULL`
- `enabled_tool_names TEXT NOT NULL`
- `activated_skill_names TEXT NOT NULL`
- `runtime_snapshot TEXT NOT NULL`
- `suspended_tool_call TEXT NULL`
- `last_active_time TIMESTAMPTZ NOT NULL`
- `created_time TIMESTAMPTZ NOT NULL`
- `updated_time TIMESTAMPTZ NOT NULL`

消息表用 `id VARCHAR(64) PRIMARY KEY` 承载 entryId，`content`/`payload` 使用 TEXT，唯一约束 `(session_id, sort_no)`；摘要表以 `session_id` 为主键并保存 `compaction_id`，用于幂等压缩提交。任何需要检索的值不能只放在 JSON TEXT 中。

## 12. 测试分层

- protocol：精确 JSON、未知字段、多态 round-trip。
- common：构造不变量、不可变集合、快照 round-trip、深拷贝。
- core-extension：编译契约和架构规则。
- core：全 Fake 端口，不启动 Spring。
- kit：纯单元测试；人工介入只断言返回结果，不操作 Store。
- runtime：真实 Spring AI 类型样本、内存存储、并发和资源生命周期；不启动 IoC。
- 依赖对齐：FND-01 declared/resolved/loaded 基线、RUN-02 前后 dependency tree/版本理由、Enforcer convergence 和 R-13 豁免清零；Spring Boot/模型供应商 SDK resolved 版本保持不变。
- platform：MockMvc/SseEmitter、Testcontainers PostgreSQL、线程池故障注入。
- memory：不编译、不测试；只验证占位 POM、归档 MANIFEST 和 archive 未进入任何生产 source/resource/classpath。
- 最终：父 reactor、前端 test/typecheck/build、源码差异和依赖树检查。
