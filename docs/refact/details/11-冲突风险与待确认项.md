# 冲突、风险与待确认项

> 目标：在编码前暴露会改变接口、状态或交付边界的问题。已确认项作为实施约束；仍标为阻塞/待确认的条目需关闭后才能固化对应实现。

## 1. 需求、设计、架构冲突矩阵

### R-01 当前数据库事实与任务基线描述不一致

- 严重级别：中

- 证据：当前 POM 启用 MySQL、注释 PostgreSQL；`application.yml` 配 PostgreSQL URL；不存在 `application-dev.yml`；Git diff没有POM修改。
- 冲突：任务 README称“用户正把MySQL驱动切PG”，后端参考称dev profile覆盖MySQL，均与当前工作区不一致。
- 推荐处理：FND-01记录事实；PLAT-03A把驱动、配置、Flyway三者作为一次目标切换，不假定存在可保留的未提交修改。
- 影响：FND-01/02、PLAT-03A、CLEAN-03。

### R-02 原始需求要求Agent配置可来自数据库，但设计把数据库Provider排除本期

- 严重级别：中
- 状态：总体设计已作范围裁剪，需产品接受
- 冲突：原始需求说配置“可以放在数据库、配置文件”；已确认设计只定义接口，本期仅Java/文件/Spring配置。
- 技术判断：接口可替换性已满足，数据库来源的实际可用性未满足。
- 推荐处理：本期验收表述为“支持未来数据库Provider扩展”，不能声称已支持数据库配置；若原需求把数据库来源视为必须交付，应新增独立任务而非塞入platform Repository。
- 影响：CORE-01、RUN-01、PLAT-01、CLEAN-03。

### R-03 “生命周期中修改Hook”语义在原始需求与已确认设计间不完全一致

- 严重级别：高
- 状态：已确认（2026-07-31），不再阻塞 CORE-01/02
- 冲突：原始需求要求Agent配置的生命周期函数、工具、Skill中除Skill外可在生命周期中修改；设计只明确AGENT_BUILD可修改定义/Hook Binding，运行期HookMutations只允许消息和enabledTools，不能重写当前Hook链。
- 已确认决策：只有 AGENT_BUILD 可以通过 `AgentDefinitionOperation` 修改最终定义，包括 Hook 配置和工具全集/default；其余生命周期只能修改 session enabledTools、消息、当前模型/工具/压缩对象，不可增删 Hook Binding。`enabledTools` 是运行态，不属于定义。
- 替代方案：若必须允许运行期动态Hook链，需要新增HookChainDelta、当前/后续生命周期生效时机、恢复快照和并发规则，属于明显二次设计。
- 影响：COM-02、CORE-01/02、恢复快照。

### R-04 MCP/SubAgent初始化失败降级与不可变定义/配置漂移规则冲突

- 严重级别：阻塞
- 状态：已确认（2026-07-31），按“禁止新绑定、旧绑定只读留痕”实施
- 冲突来源：补充决策前的设计要求初始化失败后从registry、Agent available/default和session enabled中删除并继续；同时要求Provider返回完整定义、Assembler校验available⊆registered、普通session工具漂移必须失败，且runtime“不解释业务状态”。单纯从registry删除会让所有引用该工具的定义构造失败，无法“继续”。总体设计现已按下述决策修订。
- 已确认决策：新增 `ToolAvailabilityProvider` 和结构化 health snapshot。新 session 或 AGENT_BUILD 新增不可用绑定时构造失败；已有 session 上一活动定义中已存在的绑定转为 `HistoricalToolBinding`，从有效定义、session enabled 和 ToolCatalog 移出。历史 ToolCall/ToolResult 保持展示但不能执行；挂起工具失效时生成“工具不可用”ToolResult后继续；健康恢复不得自动启用旧 session。
- 显示边界：当前外部协议和前端不增加字段，“历史可显示”由既有对话 ToolCall/ToolResult 实现；`HistoricalToolBinding` 是后端快照审计数据。若需要独立的“绑定历史”页面/API，应另立跨端需求，不能混入本期协议兼容范围。
- 代价：core增加一个端口、一类历史快照和一条例外规则；需要结构化区分“初始化故障”与普通配置缺失。
- 不推荐：runtime包装SessionRepository偷偷过滤，或Provider装饰器只改定义不改session；两者会产生状态不一致。
- 影响：COM-03、EXT-01、CORE-01/06/07B、RUN-01/06/07/08。

### R-05 core同步构造失败时HTTP与SSE行为未定义闭合

- 严重级别：阻塞
- 状态：已确认（2026-07-31），采用仅 END SSE
- 冲突来源：补充确认前，runtime设计要求Agent尚未构造时Once Publisher发END；platform又在返回emitter前同步构造，可在此时选择HTTP错误。除SessionBusy=409外，上游没有规定构造/恢复校验失败究竟返回HTTP 4xx/5xx还是仅END SSE。总体设计现已按下述决策修订。
- 当前行为：Coordinator捕获factory异常，发送END并complete，不向客户端返回错误状态。
- 已确认决策：参数/Header错误=HTTP 400；SessionBusy=HTTP 409且不发END；取得lease/绑定Publisher后的 core 构造/恢复准备失败由 runtime 通过 Once Publisher 发布唯一精确 END、释放lease并抛 `AgentPreparationException(endPublished=true)`，platform记录错误、complete并以HTTP 200返回该仅END emitter。不得追加错误事件、文本或HTTP错误映射。
- 影响：RUN-04C、PLAT-02/04、协议Golden File。

### R-08 无跨Repository事务但上游未定义幂等重试

- 严重级别：阻塞
- 状态：待确认
- 冲突：设计明确Conversation先成功、Session后失败时不回滚，也要求停止传播；但未定义客户端/服务重试如何避免重复用户消息、ToolResult或摘要。仅 `(session_id, sort_no)` 唯一约束会把合法重试变成冲突，无法判断同一操作。
- 推荐处理：common消息增加稳定entryId，压缩提交增加compactionId；Repository相同ID+相同内容视幂等成功，不同内容冲突。core在第一次写前生成ID并在同一次重试上下文保留。
- 待进一步确认：跨HTTP重试如何重用原entryId。若请求重新进入且没有客户端requestId，core只能根据已存sortNo/内容识别，仍有歧义。最低可接受范围是进程内/同execution重试幂等，跨请求部分提交由显式错误和运维修复处理。
- 影响：COM-01/03、EXT-01、CORE-03/05B/05C/06、RUN-03、PLAT-03B/C。

### R-09 挂起先持久化、后发交互事件时，发送失败会留下用户不可见的挂起会话

- 严重级别：阻塞
- 状态：待确认产品恢复策略
- 冲突：正确顺序必须先保存，否则用户看到无法恢复的prompt；但保存后SSE断开，session已HUMAN_IN_THE_LOOP，当前协议没有“查询/重放待处理交互”接口，NEW又被禁止。
- 选项A（推荐长期）：允许同一chat入口在session已挂起且请求明确为重连时重放持久化interaction，需要新增可识别重连语义；若新增RequestType则会改协议/前端。
- 选项B（本期最小）：接受极端断链会话需运维/清理，保存完整interaction payload并记录metric；在发布风险中明确。
- 不推荐：先发事件后保存，可能让用户提交永远不能恢复。
- 影响：CORE-07A、PLAT-02/04、协议范围。

### R-10 Publisher失败后的上游模型/工具取消机制未在端口中定义

- 严重级别：高
- 状态：已确认（2026-07-31），采用请求级主动取消命令且不等待超时
- 风险：当前 MessageUtils只warn，客户端断开后模型仍运行/工具仍执行；即使抛异常，reactive subscription也需显式dispose。
- 已确认决策：common 提供请求级 `CancellationToken.onCancel(command)`；runtime 的 execution 持有唯一 source 和活动注册表，`cancel()`/`close()` 对 RUNNING 只发命令并立即返回。ModelStreamObserver、ToolExecutionObserver、ToolExecutionContext 共享同一 token，默认模型、HTTP/SubAgent、MCP adapter 必须注册 dispose/cancel/close。runtime close 对活动 execution 逐一发命令，不等待、不设置取消超时或 grace period；lease 只由实际执行 finally 释放。不合作的自定义工具可能长期占用资源，作为公开限制。若取消时 Assistant ToolCall 已持久化，core 为未完成调用补标准取消结果以保持后续模型历史配对。
- 影响：EXT-01、CORE-04/06、RUN-02/04C/06/07、PLAT-02。
