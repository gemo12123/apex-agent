## 1. 执行原则

- 本清单是文件级协调索引，不新增或拆分现有 50 个子任务；每个工作集的详细内容、验收标准和限制仍以对应任务文件为准。
- 各工作集状态应随对应任务文件同步更新；当前 `00` 进行中，`01`～`05` 已完成，`06`～`09` 未开始。
- `00-工程基线与模块骨架.md` 同时包含最早执行的 FND-01～03A 和最终收口的 FND-03B，因此需要在开始和收尾阶段两次进入，但仍由同一工作集负责人维护。
- `09-清理与整体验收.md` 先完成 CLEAN-01/02，再等待 FND-03B，最后完成 CLEAN-03。
- `04-core模块.md` 与 `05-kit模块.md` 可以受控并行；KIT-01/02 已完成联调契约，CORE-07A～07C 可在 core 工作集内继续实施。
- `07-platform模块.md` 与 `08-memory模块.md` 可以受控并行；memory 只做非编译历史归档和占位模块，归档前必须确认正式替代实现已落入 core、runtime 或 platform。
- 父 POM、公共 record、扩展接口和 PostgreSQL migration 等共享修改点必须由其唯一责任任务串行合并。

## 2. 总体顺序

```text
00（FND-01～03A）
  -> 01
  -> 02
  -> 03
  -> 04 || 05
  -> 06
  -> 07 || 08
  -> 09（CLEAN-01/02）
  -> 00（FND-03B）
  -> 09（CLEAN-03）
```

其中 `||` 表示满足前置依赖、且不并发修改同一共享文件时可以并行。

## 5. 状态维护约定

状态统一使用以下值：

- `未开始`：尚未产生可验收实现。
- `进行中`：工作集已开始，但尚未满足全部验收标准。
- `受阻`：存在已记录且必须由外部决策或条件解除的阻塞项。
- `已完成`：生产实现、测试、架构约束和文档要求均已验收。

只完成部分子任务时，文件级状态仍为“进行中”；不得因单个子任务通过就把整个工作集标记为“已完成”。
