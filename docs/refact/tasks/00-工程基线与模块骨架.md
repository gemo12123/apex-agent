# 工程基线与模块骨架任务

> 任务域：跨模块工程基础
> 当前总体进度：未开始；仅存在用户对 PostgreSQL 驱动的局部未提交修改

## FND-01 冻结现有行为与协议基线

- **任务名称**：冻结重构前核心行为与线协议。
- **任务目标**：为迁移后的新链路提供可重复对比的行为基准，防止重构误改 HTTP/SSE、Turn/Iteration、多工具和人在回路语义。
- **当前进度**：部分具备。已有 44 个测试文件，设计文档记录 137 个测试通过；尚未重新验证，也未确认全部要求场景和 Golden File 已覆盖。
- **设计依据**：设计文档第 20 节阶段 0、第 21.7 节；架构文档第 18.4 节；原始需求第 4 条。
- **涉及范围**：当前单模块的 `src/test`；现有 `ChatController`、`ChatService`、`SuperAgent`、工具处理、人工介入和消息序列化测试；协议样本资源。
- **前置依赖**：无。必须在生产代码大规模迁移前完成。
- **具体执行内容**：
  1. 运行并记录现有后端测试基线、测试数和失败项。
  2. 补充普通无工具 Turn、多 Iteration、多 ToolCall 前序成功后序挂起、`ask_human`、工具确认、已执行 PRE Hook 不重复等特征测试。
  3. 为 `STREAM_CONTENT`、`ASK_HUMAN`、`TOOL_CONFIRMATION`、`END` 及保留兼容 DTO 建立精确 JSON Golden File。
  4. 固定 `context.mode="react"`、不输出 `stage_id`、`END` 精确为 `{"event_type":"END"}`。
  5. 记录现状与已确认设计冲突，不用特征测试固化明确要求删除的 PlanExecutor 行为。
  6. 记录 Spring AI/Spring AI Alibaba/Spring Framework 相关 declared/resolved dependency tree、BOM/显式覆盖来源、实际加载类的 jar 版本，以及 ChatModel、Message、ChatResponse、ToolCall、ToolResponse、ChatOptions 等 RUN-02 关键 API 签名。
- **预期产出**：基线测试清单、缺口测试、Golden File、可复现的基线执行记录和 Spring AI 依赖/API 基线报告。
- **验收标准**：
  - `mvn -f apex-agent/pom.xml test` 在基线提交上通过，或对已有失败给出可复现且经确认的豁免清单。
  - 六类核心场景均有自动化测试，Golden File 可在 protocol/platform 迁移后复用。
  - JSON 断言覆盖字段名、空字段、事件类型和多态反序列化，不只比较 Java 对象。
  - 依赖/API 基线能回答每个关键类型“声明版本、解析版本、实际 jar、关键方法签名”，并保存生成命令和原始 dependency tree 证据。
- **限制条件或注意事项**：本基线任务不得修改前端；不得把 PlanExecutor 生产行为作为目标态要求；Q-14 的前端刷新增量在 PLAT-04 单独实施和验收。若当前协议与设计冲突，停止修改目标值并登记问题。

## FND-02 建立父 POM、临时 legacy 与八模块骨架

- **任务名称**：把单模块工程改造为迁移期可运行的 Maven Reactor。
- **任务目标**：先用临时 `legacy` 模块承载全部现有源码、测试和资源，再建立八个目标模块，避免根 POM 改为 `packaging=pom` 后旧链路退出构建。
- **当前进度**：未开始。八个目标目录均不存在；当前 `apex-agent/pom.xml` 仍是单模块 POM。PostgreSQL 驱动局部修改不代表该任务完成。
- **设计依据**：设计文档第 2.34、4.2、20 节阶段 1；架构文档第 4.2、4.3 节。
- **涉及范围**：`apex-agent/pom.xml`、临时 `legacy/pom.xml`、八个目标模块 POM、现有根 `src/main`/`src/test`/资源的整体迁移、Maven Compiler/Surefire/Enforcer/Boot 插件配置。
- **前置依赖**：FND-01。
- **具体执行内容**：
  1. 在 FND-01 基线通过后创建临时 `legacy` 模块，将现有根目录生产源码、测试和运行资源整体迁入，保持包名、启动类和行为不变。
  2. 把根 POM 改为父聚合 POM，同时聚合 `legacy` 与八个目标模块，统一坐标、JDK 25、UTF-8、LF、依赖和插件版本。
  3. 迁移初期由 `legacy` 继续执行 Spring Boot repackage；platform 接管后取消该豁免，最终只有 platform repackage。
  4. 创建八个目标模块及最终依赖方向。迁移期只允许 `legacy -> 目标模块`，禁止任何 `目标模块 -> legacy`。
  5. 按真实直接引用声明项目依赖：common→protocol；core-extension→protocol/common；core、kit→protocol/common/core-extension；runtime→protocol/common/core-extension/core/kit；platform→protocol/common/core-extension/runtime；memory 为无依赖 `packaging=pom` 归档占位模块。
  6. 建立临时豁免清单：旧 Spring/数据库/Fastjson/PlanExecutor 依赖随对应模块迁移逐项缩减；PlanExecutor 在 CLEAN-01 到期，SuperAgent/重复 Hook/legacy 模块在 CLEAN-02 到期。
  7. 将用户现有 PostgreSQL 驱动修改在 PLAT-03A 中迁入 platform 子 POM，保留其意图且不覆盖无关修改。
  8. 将当前 Spring AI 多版本组合集中到父 dependencyManagement，但不在 FND-02 猜测目标版本；若 convergence 尚未通过，只登记 owner=RUN-02、expires-at-task=RUN-02 的精确坐标豁免，不得关闭全局 convergence。
- **预期产出**：父 POM、可运行 legacy、八个目标模块骨架、临时依赖豁免清单和迁移切换说明。
- **验收标准**：
  - 父 POM 切换后，`mvn -f apex-agent/pom.xml test` 同时执行 legacy 基线测试和目标模块测试。
  - `mvn -f apex-agent/pom.xml -pl legacy test` 通过，旧 Spring Boot 入口仍可启动。
  - 目标模块依赖符合最终依赖图且无任何模块依赖 legacy；legacy 的临时反向依赖均有到期任务。
  - 迁移期 repackage 豁免仅属于 legacy，且明确由 CLEAN-02 删除；最终验收仍要求只有 platform repackage。
  - 文件编码为 UTF-8、换行为 LF，构建不依赖机器绝对路径。
  - Spring AI 收敛豁免只覆盖基线证明存在冲突的精确坐标，并明确在 RUN-02 到期。
- **限制条件或注意事项**：整体移动源码不等于修改业务语义；不得在 FND-02 重写旧链路。所有父 POM 和 legacy 豁免修改必须串行合并；FND-02 不主动升级依赖，只为 RUN-02 保留 Q-17 允许的条件式最小调整入口。Spring Boot 和模型供应商 SDK 版本仍禁止调整。

## FND-03A 建立架构测试基础设施

- **任务名称**：建立可逐步扩展的架构测试基础设施。
- **任务目标**：先提供 Maven Enforcer、ArchUnit 或等价测试入口，不等待各模块规则全部完成。
- **当前进度**：未开始。
- **设计依据**：设计文档第 21.1 节；架构文档第 18.1 节。
- **涉及范围**：父 POM、架构测试承载位置、ArchUnit/Maven Enforcer 或等价工具、迁移期豁免格式。
- **前置依赖**：FND-02。
- **具体执行内容**：
  1. 建立由父 reactor `test` 或 `verify` 自动执行的架构测试入口。
  2. 先检查目标模块不得依赖 legacy、Maven 模块依赖无环和未声明依赖。
  3. 定义模块规则注册方式，使 PRO、COM、EXT 和后续模块可以独立追加规则。
  4. 为迁移期豁免定义“规则、原因、责任任务、到期任务”四项必填字段。
  5. 启用 dependency convergence，并允许 FND-02 登记的精确 Spring AI 冲突暂时豁免至 RUN-02；禁止按整个 groupId 或全局关闭规则。
- **预期产出**：架构测试基础设施、最小依赖规则和豁免登记机制。
- **验收标准**：
  - 父 reactor 自动执行架构测试。
  - 人为添加 `目标模块 -> legacy` 或循环依赖时测试失败。
  - 人为删除 core-extension 的 protocol 直接依赖时，dependency analyze/compile 因 AgentMessage 直接引用而失败。
  - 后续模块可在不复制基础设施的情况下注册专项规则。
  - Spring AI 豁免缺少具体坐标、基线证据或 RUN-02 到期任务时验证失败。
- **限制条件或注意事项**：本任务不宣称全量架构规则完成；不得使用无到期任务的宽泛包名豁免。

## FND-03B 收口最终全模块架构规则

- **任务名称**：完成八模块最终架构规则和 legacy 豁免清零。
- **任务目标**：在所有模块迁移及 legacy 删除后，把完整设计边界变成自动构建门槛。
- **当前进度**：未开始。
- **设计依据**：设计文档第 21.1、22 节；架构文档第 18.1 节。
- **涉及范围**：FND-03A 基础设施、各模块专项规则、父 POM、依赖树和迁移期豁免清单。
- **前置依赖**：EXT-03、PRO-01、COM-01、CORE-07C、RUN-08、PLAT-04、MEM-03、CLEAN-01、CLEAN-02。
- **具体执行内容**：
  1. 汇总 protocol、common、core-extension、core、kit、runtime、platform、memory 的全部禁止依赖和类型规则。
  2. 检查 core-extension 顶级类型全为 interface，common 无 Spring，core/runtime 依赖方向符合设计；memory 无标准 source root、依赖或编译插件，archive 未被其他模块扫描。
  3. 检查 runtime 不分发 AGENT_BUILD、不复制 core 定义构造状态机。
  4. 检查依赖树无 Fastjson/fastjson2、无 legacy 模块、无过期豁免。
  5. 检查每个模块的直接项目依赖与目标表一致，used-but-undeclared 为零。
  6. 将全部规则纳入父 reactor 标准验证。
  7. 检查 R-13 临时豁免已删除，Spring AI 生态每个关键 artifact 只解析到一个版本，版本全部由父 POM/BOM 所有。
- **预期产出**：最终全模块架构测试和已清零的迁移豁免清单。
- **验收标准**：
  - 每条目标架构约束至少有一个自动断言。
  - 父 reactor 验证通过，且模块清单严格为八个目标模块。
  - 人为加入典型非法类型或依赖时对应规则失败。
  - Enforcer convergence 无 Spring AI 例外；最终依赖树与 RUN-02 对齐报告一致。
- **限制条件或注意事项**：这是最终收口任务，不作为 EXT-03 的前置；最终验收不得保留 legacy 专用规则例外。
