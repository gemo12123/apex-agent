# 项目分层
项目将由 protocol、common、core-extension、core、kit、runtime、platform、memory 这几个模块来实现
protocol: 公共协议模块，用来维护消息标准对应的实体类，所有前后端交互的消息实体类都应该由模块来维护；。
common: 公共模块，用来维护公共的实体类，只有跨模块的实体类才会被放到其中，其引入了protocol模块；只引入一些通用的公共依赖（如：commons-lang3），不引入项目依赖（如：spring相关依赖）。
core-extension：用来声明一些扩展接口、声明周期接口等，其中只包括接口定义，不含任何实现
core：智能体核心模块，用来维护主循环、上下文工厂、上下文、各种生命周期函数、持久化接口等，其引入common模块、core-extension；只引入一些通用的公共依赖（如：commons-lang3）和最小范围的项目依赖（如：spring ai相关依赖）。
kit：基础组件，用来存储一些基础工具、生命周期函数的扩展等，引入core-extension模块
runtime：基础运行时模块，提供默认的各种基础扩展（例如基于内存的会话存储）和默认智能体的定义，其引入core模块、kit模块；只引入一些通用的公共依赖（如：commons-lang3）和最小范围的项目依赖（如：spring ai相关依赖），保证外部项目只引入runtime通过new对象即可成功运行一个智能体
platform：平台模块，用于与前端交互，创建智能体、维护智能体状态、实现数据持久化层，其引入runtime模块，并在runtime的基础上将基于内存的存储扩展成基于PG数据库的存储，引入全部项目依赖（如：spring相关依赖）
memory：存储当前的关于memory、skill learning，这个模块暂时只保留当前功能现状，不被任何模块基础，属于暂时封存的状态

# 功能要求
1. core包中维护主循环，只做循环的定义、声明周期的使用等，一切基于接口开发，接口的定义放在core-extension，方便后期扩展
2. agent的定义由配置生成，这个配置可以放在数据库、配置文件，通过接口屏蔽实现细节，agent可以配置声明周期函数、工具、skill，且必须允许在声明周期中修改这些内容；工具可以配置全集和默认启用集合，在运行过程中通过声明周期函数来动态改变已启用工具集合，只有已启用工具集合才放到大模型的入参中
3. 消息的发送在core中也是发送到接口中，runtime只做一个基于print的实现即可，platform中再写入sseemitter中
4. 声明周期函数在现有的八个（Turn开始、循环开始、模型调用前、模型调用后、工具执行前、工具执行后、循环结束、Turn结束）基础上，增加构造智能体的声明函数
