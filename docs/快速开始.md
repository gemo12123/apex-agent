# 快速开始

## 目标

本文档按“尽量少踩坑”的方式启动当前仓库：

- 先跑通后端主链路
- 再跑前端工作台
- 最后再按需接入外部 MCP、Skills 与 JDBC 记忆

## 环境准备

必需：

- `JDK 25`
- `Maven 3.9+`
- `Node.js 20+`
- `DASHSCOPE_API_KEY`

可选：

- PostgreSQL
- `pgvector`

说明：

- 当前默认记忆存储是 `in-memory`，不需要数据库也能先跑起来
- 只有在你准备启用 JDBC 记忆与 `session_search` 持久化检索时，才需要继续配置数据库

## 第一步：检查后端配置

后端主配置文件：

- `apex-agent/src/main/resources/application.yml`

注意 `application.yml` 里 `spring.profiles.active: dev`，`application-dev.yml` 会覆盖部分配置：数据源变为 MySQL、`apex.memory.enabled: false`（记忆链路整体关闭），且不含 `apex.skills.learning` 配置。默认启动形态就是这个 dev 覆盖后的结果。

你至少要关注四块内容。

### 1. 模型密钥

PowerShell 示例：

```powershell
$env:DASHSCOPE_API_KEY="your-api-key"
```

### 2. 记忆存储类型

当前默认值：

```yaml
apex:
  memory:
    store:
      type: in-memory
```

如果只是先验证主链路，保持默认即可。

### 3. 外部 MCP / Skill 示例路径

`application.yml` 当前包含这类示例配置：

- `apex.global.mcps.meeting-server`
- `apex.global.mcps.contacts-server`
- `apex.global.skills.meeting-skill`
- `apex.global.skills.contacts-skill`

这些路径指向作者本地绝对路径，不是仓库自带资源。你有两种做法：

1. 改成你自己的真实路径
2. 暂时保留，先只验证无外部依赖时的主流程

当前实现里，即使这些外部资源不存在，服务通常仍可启动；对应 agent 在真正装配工具时会记录告警并跳过缺失资源。

### 4. Agent workspace 现实情况

仓库内当前只有这些内置 workspace 资源：

- `apex-agent/src/main/resources/agents/codex/REACT_PROMPT.md`
- `apex-agent/src/main/resources/agents/deer-flow/REACT_PROMPT.md`
- `apex-agent/src/main/resources/agents/deer-flow/config.yml`

因此请把 `application.yml` 中的 agent 声明理解为“配置入口”，而不是“仓库全部内置 agent 文件都已经齐全”。

## 第二步：启动后端

在仓库根目录执行：

```bash
cd apex-agent
mvn spring-boot:run
```

默认监听地址：

- `http://localhost:18083`

## 第三步：验证后端接口

所有请求都必须带 `X-User-Id`。

### 1. 获取 agent 列表

```bash
curl -H "X-User-Id: demo-user" http://localhost:18083/api/sse/agents
```

预期返回类似：

```json
{
  "code": 200,
  "data": [
    {
      "agentKey": "default_agent",
      "name": "通用智能体"
    }
  ],
  "message": "success"
}
```

### 2. 发起一轮 SSE 会话

```bash
curl -N \
  -H "Content-Type: application/json" \
  -H "X-User-Id: demo-user" \
  -X POST http://localhost:18083/api/sse/chat \
  -d '{
    "sessionId": "session-001",
    "agentKey": "default_agent",
    "query": "请介绍一下你当前有哪些能力",
    "type": "NEW"
  }'
```

你会收到按行推送的 SSE 消息，事件结构见 [消息标准](消息标准.md)。

### 3. 恢复 `ask_human` 或工具确认挂起的会话

恢复请求同样走：

- `POST /api/sse/chat`

请求体里的 `type` 改为 `HUMAN_RESPONSE`。
如果是 `ask_human`，前端/调用方要按 `tool_call_id -> answers` 组织答案；如果是 `TOOL_CONFIRMATION`，则要回传确认结果与可选的 `updated_args`。

## 第四步：启动前端工作台

另开一个终端：

```bash
cd apex-frontend
npm install
npm run dev
```

默认地址：

- `http://localhost:5173`

Vite 会把 `/apex-api/*` 代理到：

- `http://localhost:18083/api/*`

也就是说，前端默认按“本地后端 + 本地工作台”开发模式工作，不需要你额外改前端 API 地址。

## 第五步：使用前端工作台验证主流程

前端当前支持的主流程：

- 选择 agent
- 设置 `userId`
- 发起第一条消息
- 查看正文流
- 查看阶段、工具调用、产物
- 响应 `ASK_HUMAN`
- 响应 `TOOL_CONFIRMATION`

如果后端收到 `END` 事件且没有挂起交互，前端会把当前会话状态标记为 `completed`。

## 可选：启用 JDBC 记忆

如果你要切换到 JDBC：

```yaml
apex:
  memory:
    store:
      type: jdbc
```

还需要同步处理下面几个问题。

### 1. 数据源配置

环境变量：

- `APEX_MEMORY_DATASOURCE_URL`
- `APEX_MEMORY_DATASOURCE_USERNAME`
- `APEX_MEMORY_DATASOURCE_PASSWORD`

### 2. schema 初始化

当前仓库提供的 schema 文件是：

- `apex-agent/src/main/resources/db/memory-schema-postgresql.sql`

### 3. PostgreSQL / 驱动对齐

源码里的 JDBC 记忆和 `session_search` 逻辑围绕 PostgreSQL + `pgvector` 展开，但 `pom.xml` 当前保留的是 MySQL 驱动，并注释掉了 PostgreSQL 驱动。
如果你真的要启用 JDBC，请先自行对齐：

- Maven 驱动依赖
- `spring.datasource.driver-class-name`
- PostgreSQL 实例
- `pgvector`

## 常见问题

### 1. 接口直接返回 400

先检查：

- `sessionId` 是否为空
- 是否遗漏 `X-User-Id`

### 2. 启动后能拉 agent 列表，但会话里缺 MCP / Skill

这是当前最常见情况，通常因为：

- `application.yml` 里的 MCP 命令指向本地不存在的脚本
- skill 目录是示例绝对路径

这不一定会阻止服务启动，但会让对应资源在运行时被跳过。

### 3. 想先验证最小可用链路

建议先保持：

- `apex.memory.store.type=in-memory`
- 使用不依赖外部资源的最小 agent 配置
- 暂时不接 MCP、SubAgent、Skills

这样最容易先确认：

- SSE 会话能建立
- 模型能响应
- 前端能消费消息协议
