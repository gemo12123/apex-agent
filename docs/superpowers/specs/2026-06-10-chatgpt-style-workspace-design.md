# ChatGPT 风格工作台改版设计

日期：2026-06-10
状态：待评审

## 1. 背景

当前 `apex-frontend` 的工作区已经具备完整的核心能力：

- 欢迎态任务发起
- 会话流式输出
- 人工确认与工具确认
- 执行轨迹展示
- 产物详情查看与导出

但现有界面结构更像“表单控制台 + 对话区 + 右侧双面板”，与用户期望的 ChatGPT 首页/工作区体验存在明显差异：

- 欢迎态和会话态像两个产品，切换时有明显跳页感
- 顶部 header、右侧双面板和中间消息区竞争注意力
- `Agent`、`用户 ID` 等工作入口占据过高视觉层级
- 执行轨迹能力存在，但组织方式偏后台，不像对话产品中的次级侧栏

这次改版的目标不是新增业务能力，而是把现有能力重新组织成更接近 ChatGPT 桌面版的工作区体验，同时保留 Apex 的执行追踪差异化能力。

## 2. 问题总结

当前前端在体验层面有五个具体问题。

### 2.1 首页与工作台割裂

`WelcomeScreen` 和 `WorkspacePage` 是两套明显不同的页面，用户从欢迎态进入会话后会感受到“跳到另一个系统”。

### 2.2 对话不是唯一主视角

顶部 header、右侧执行轨、右侧详情面板都在抢主视觉，导致中间对话区不够像 ChatGPT 那种单核心阅读体验。

### 2.3 工作入口层级过高

`Agent`、`用户 ID`、返回首页等控件当前直接暴露在主区域，像管理台表单，不符合用户对聊天产品首页的预期。

### 2.4 执行轨迹组织方式偏重

当前 `ExecutionRail + DetailPanel` 采用“列表 + 独立详情”的后台式布局，阅读路径被切断，不适合做成可临时唤出的右侧侧栏。

### 2.5 中文文案编码异常

多个前端文件中的中文已出现乱码，直接影响界面质感和这次改版的最终表现。

## 3. 目标

- 让欢迎态和会话态共用同一套工作台外壳。
- 让中间对话区成为页面唯一主视角。
- 左侧固定为 ChatGPT 风格导航栏，默认展开。
- 右侧执行轨迹默认隐藏，按需唤出。
- `Agent` 选择前置到新建会话附近，`用户 ID` 保留在底部次级区域。
- 将执行轨迹与详情合并成单一时间线抽屉。
- 保留现有会话状态机、确认交互和产物导出能力。
- 修复本次涉及界面的中文乱码问题，统一恢复为 UTF-8 正常文案。

## 4. 非目标

- 本次不实现真实历史会话数据加载
- 本次不修改后端 SSE 协议
- 本次不新增新的执行事件类型
- 本次不重构 session store / reducer 的核心状态机
- 本次不改变 `NEW / HUMAN_RESPONSE` 语义
- 本次不处理与本次工作台改版无关的广泛样式重构

## 5. 已确认的用户决策

本次设计基于以下已确认决策：

- 欢迎态与会话态都改成统一风格
- 视觉目标尽量贴近官方 ChatGPT 桌面版观感
- 左侧栏保留轻量工作入口，而不是完全极简
- 左侧栏默认展开
- 右侧执行轨迹为手动唤出的挤压式侧栏
- 右侧内容组织为单条可滚动时间线
- 默认主题为浅色优先
- `Agent` 选择放在新建会话附近
- `用户 ID` 放在左侧栏底部次级区域

## 6. 选定方案

采用“官方复刻优先”的方案 A。

理由：

- 最接近用户要求的 ChatGPT 首页/工作区观感
- 能用最少的主视觉元素承载欢迎态和会话态
- 允许 Apex 的执行轨迹能力退居次级侧栏，而不是压过对话主区
- 在保留业务能力的前提下，改动路径最清晰

允许的偏离点：

- 为满足工作流需要，`Agent` 选择会比原始 ChatGPT 更靠前
- 右侧执行轨迹是 Apex 特有能力，会作为可唤出的次级侧栏保留

## 7. 目标信息架构

整个页面收敛为三块区域：

1. 左侧导航栏
2. 中间主工作区
3. 右侧执行时间线抽屉

其中默认只显示前两块。右侧抽屉只有在用户主动打开时才参与布局。

### 7.1 左侧导航栏

职责：

- 发起新会话
- 选择当前 `Agent`
- 展示历史对话占位结构
- 承载用户级次级设置

结构：

- 顶部
  - `新建会话` 主按钮
  - `Agent` 选择入口
  - 可选轻量入口，如 `搜索对话`
- 中部
  - `历史对话` 标题
  - 历史列表占位 / skeleton / 空状态
- 底部
  - `用户 ID` 入口或摘要

约束：

- 左栏整体视觉应接近 ChatGPT 的附属导航，而非管理台表单区
- 中部列表优先使用轻量条目，不使用重卡片
- `用户 ID` 默认只显示摘要，交互展开后才出现输入控件

### 7.2 中间主工作区

职责：

- 作为全页面唯一主视觉
- 承载欢迎态、消息流、确认卡片与输入区
- 作为打开右侧时间线的入口承载区

结构：

- 顶部不再保留当前大 header
- 主区域根据会话状态切换：
  - 空会话：欢迎文案 + 大输入框 + 建议问题
  - 已开始会话：消息流
- 底部固定为统一输入区

### 7.3 右侧执行时间线抽屉

职责：

- 展示计划、调用、产物、确认、结束状态的统一时间线
- 提供单节点展开查看能力
- 不承担编辑职责

默认行为：

- 默认关闭
- 通过中间区次级按钮打开
- 打开时挤压中间区宽度

## 8. 页面状态设计

### 8.1 欢迎态

欢迎态应接近 ChatGPT 首页：

- 一句简短欢迎文案
- 一个居中的大输入框
- 3 到 4 个轻量建议问题

明确移除或弱化以下内容：

- 当前较重的产品介绍大卡片
- 顶部页头式控制区
- 长表单式 `Agent / 用户 ID` 直接暴露

欢迎态仍位于同一工作台外壳中，而不是独立页面。

### 8.2 会话态

会话开始后：

- 欢迎文案和建议问题淡出
- 同一区域切换为消息流
- 输入区保持在相同位置，不产生跳页感

这样可以让欢迎态和会话态共享：

- 同一套宽度约束
- 同一套留白节奏
- 同一套输入器位置
- 同一套视觉语言

## 9. 中间对话区设计

### 9.1 消息视觉语言

用户消息：

- 保留右侧气泡
- 使用更克制的浅灰胶囊感

助手消息：

- 弱化整块边框卡片感
- 优先依靠排版、段落留白和 Markdown 层级呈现

`think` 内容：

- 保留折叠能力
- 文案改为更自然的“推理过程”或“执行思路”
- 视觉上弱于正文，不喧宾夺主

### 9.2 确认卡片

`HumanPromptCard` 与 `ToolConfirmationCard` 仍插入消息流中处理，不迁移到侧栏。

改版方向：

- 统一为“内嵌任务卡”
- 与主消息区共享同一套圆角、边框和留白语言
- 不能再像独立后台表单模块

### 9.3 输入区

输入区是最重要的固定元素，欢迎态与会话态共用。

结构：

- 大圆角输入容器
- 主发送动作在右下
- 停止流式输出、轨迹入口等降为次级控件

状态要求必须保持不变：

- `streaming` 时不可发新消息
- `waiting-human` 时不可发新消息
- `waiting-confirmation` 时不可发新消息

但提示文案要更自然，避免出现“像报错”的状态感。

## 10. 左侧栏交互设计

### 10.1 新建会话

`返回首页` 文案取消，统一改为 `新建会话`。

语义沿用当前 `resetSession()`：

- 清空当前 session 视图
- 保留 `Agent`
- 保留 `用户 ID`
- 中间主区回到欢迎态

### 10.2 Agent 选择

`Agent` 作为高频工作入口前置到左栏顶部，靠近 `新建会话`。

设计目标：

- 切换新会话前足够顺手
- 不进入中间主视觉
- 保持比底部设置更高，但低于主输入区的注意力层级

### 10.3 用户 ID

`用户 ID` 保留在左栏底部次级区域。

展示策略：

- 默认展示当前值摘要
- 需要修改时展开输入控件

## 11. 右侧执行时间线设计

### 11.1 打开方式

中间工作区右上放轻量“轨迹”入口。

行为：

- 默认关闭
- 打开后右侧插入固定宽度抽屉
- 桌面端宽度建议 `360px - 420px`
- 首选实现宽度：`380px`

桌面端采用挤压式，而不是覆盖式。

### 11.2 内容组织

不再保留 `ExecutionRail` 上半区与 `DetailPanel` 下半区的组合。

统一改为单滚动时间线，按事件顺序展示：

- 阶段开始与阶段状态变化
- 工具调用
- 产物生成
- 人工确认 / 工具确认
- 结束状态

每个节点共用统一卡片骨架，仅通过图标、标题、副标题、状态色区分类型。

### 11.3 展开规则

- 点击节点后直接在该节点内展开详情
- 同一时间只展开一个节点
- 再次点击同节点可收起

详情要求：

- 支持 Markdown 预览
- 调用节点展示参数与结果摘要
- 产物节点展示内容预览与导出按钮

### 11.4 联动规则

右侧时间线是辅助视角，不驱动主消息区滚动。

新事件到来时：

- 右栏关闭：不强制打扰，只在轨迹按钮显示轻量状态提示
- 右栏打开：时间线追加新节点，但不强制切换当前展开项

### 11.5 空状态

无执行数据时显示轻量空状态文案，例如：

“执行开始后，这里会显示计划、调用和产物时间线。”

若已有数据但无选中项，则默认展开最新关键节点。

## 12. 响应式行为

### 12.1 桌面端

- 左侧栏默认展开并长期可见
- 右侧时间线默认关闭
- 打开右侧时间线后采用挤压式布局

### 12.2 中等宽度

- 左侧栏允许折叠成窄栏，但默认仍展开
- 右侧时间线仍优先挤压中间区

### 12.3 窄屏 / 手机

- 左侧栏切为抽屉
- 右侧时间线切为覆盖式抽屉
- 两个抽屉不应同时展开

## 13. 对现有代码结构的影响

### 13.1 `WorkspacePage.vue`

从“完整页面 + header + 双侧内容编排”收敛为“纯布局壳”：

- 左栏
- 中间主区
- 右侧时间线抽屉

当前顶部 header 基本移除。

### 13.2 `WelcomeScreen.vue`

不再作为独立整页，更像中间主区的空会话状态。

### 13.3 `ChatPane.vue`

吸收欢迎态切换与统一输入区职责，成为中间主区核心组件。

### 13.4 `ExecutionRail.vue` 与 `DetailPanel.vue`

不再以现有组合存在。

目标是收敛为新的统一右侧抽屉组件，例如 `TimelineDrawer`。

### 13.5 Store 影响

保留现有会话状态机与数据来源。

允许的收敛：

- 将“选中调用 / 选中产物”统一抽象为“当前选中的时间线节点”

不做的事情：

- 不大改 reducer 的事件归并逻辑
- 不调整 SSE 协议模型

## 14. 实现边界

本次实现只处理前端信息架构、组件组织与视觉层次重构。

明确包含：

- 工作台统一壳子
- 左栏重组
- 中间欢迎态/会话态统一
- 右侧时间线抽屉
- 相关文案与乱码修复

明确不包含：

- 历史会话真实数据接入
- 后端接口新增
- 协议层变更
- 与本次改版无关的样式大清洗

## 15. 风险与约束

### 15.1 最大风险是行为回归，不是样式

必须原样保住：

- 主输入禁用逻辑
- `pendingPrompts` 渲染在消息流中
- `pendingConfirmations` 渲染在消息流中
- artifact 导出能力
- `resetSession()` 保留 `Agent` 与 `用户 ID`

### 15.2 右侧抽屉不能喧宾夺主

即便右侧信息很重要，也只能是次级视角。主阅读路径必须仍是中间对话流。

### 15.3 `Agent` 前置带来轻微“工具化”偏移

这是允许的、可控的偏移，因为它换来了更顺手的新会话工作流。

## 16. 测试策略

### 16.1 组件与视图级测试

应补充或更新以下测试：

- 欢迎态与会话态切换
- `新建会话` 是否正确回到欢迎态
- 左栏 `Agent` 入口展示与切换
- 右侧时间线展开/收起
- 时间线节点选中、切换与收起

### 16.2 行为回归测试

必须覆盖：

- `streaming / waiting-human / waiting-confirmation` 的输入禁用
- `pendingPrompts`、`pendingConfirmations` 的渲染位置
- artifact 导出是否仍可用

### 16.3 响应式验证

至少验证：

- 桌面端默认左栏展开、右栏关闭
- 打开右栏后中间区被挤压而不是覆盖
- 窄屏时左右侧栏都能退化为抽屉

## 17. 决策总结

本次批准进入实现计划的方向是：

- 采用 ChatGPT 风格统一工作台外壳
- 左栏默认展开，承担 `新建会话 + Agent + 历史占位 + 用户 ID`
- 中间主区统一承载欢迎态、会话态、确认卡片与输入区
- 右侧执行区改为默认隐藏的挤压式时间线抽屉
- 执行轨迹与详情合并为单条可展开时间线
- 保持现有业务状态机不变，只重组前端表现层
- 将本次涉及界面的中文乱码修复纳入同一轮实现
